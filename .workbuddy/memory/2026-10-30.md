## Quelmara v3.09 — 批量接收 O(n²) → O(n)（性能）

发现 `std/net` 六个接收函数都是 `out = out + part`：4 MB / 4 KB 分块累计复制约 2 GB，
直接 `heap_limit_mb exceeded`（v3.07 在发送侧修过同类坑，接收侧没跟上；t164 用
64 KB 分块掩盖了它）。改成私有 `_recv_buf`（一次分配 + 翻倍扩容 + 原地 mem_copy +
末尾 mem_str）。4 MB/4 KB：堆爆 → 75 ms；4 MB/64 KB：191 → 80 ms（2.4×）。提交 `264d3cd`。

## 项目要点（下次接手先看这几条）

- 本机是 Windows/aarch64？不是：win32 x64。原生后端默认产 **ELF**，要跑必须用
  `tools/stage0/qlm_pe.py build`（PE32+），`qlm_native.py` 是 Linux ELF 路径。
- 全量回归 `python tests/run_win_tests.py` 约 10.5 分钟，输出 `PASS=302 FAIL=0 SKIP=1`。
- 文档门禁两条：`python tools/dev/check_docs.py`（版本号同源/数字单一来源）、
  `python tools/dev/gen_stdlib_doc.py --check`（03-stdlib 与源码同源）。
- `03-stdlib.md` **只能**用 `gen_stdlib_doc.py` 重生成；用 `qlm_cli.py doc std -o` 会把
  它覆盖成裸 dump（踩过）。
- 提交时 `git -c core.safecrlf=false commit`，否则 LF/CRLF 警告刷屏。
- 一次任务 = 一个版本文件夹 + 一个 commit（docs/00-convention.md）。
