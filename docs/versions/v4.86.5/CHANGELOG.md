# v4.86.5 — 循环深度加权分配：`b22_knapsack` -34.4%

- 日期：2026-11-09
- 任务：性能优化逐项档案第 5/21 项（父版本 v4.86 的寄存器分配改动）
- 影响面：编译器（`bootstrap/qlmc/qlmc.qma` 的 `_alloc_vars`）

## 背景

`_alloc_vars` 原来按"变量在 IR 里**出现几次**"排序决定谁进寄存器。但出现次数
不等于执行次数：循环体里的一次使用每轮都要跑，循环外的一次只跑一次。两者同权，
于是**热循环变量被挤到帧槽**，每轮两次 `store`→`load` 往返。

修法：先算每条 IR 的循环嵌套深度（扫回边，`(h, e]` 内 +1），使用次数按
`4^depth` 累加（深度截到 6）。4 让"内层用 1 次"胜过"循环外用 4 次"，又不会让
深循环里的短命临时值把外层变量全挤掉。**只换位置、不改语义**。

## 本项

**基准**：`bench/speed/quelmara/b22_knapsack.qma`

**根因**：内层递减计数器 `c` 与 `cand` 溢出；`wt.get(it)`/`vl.get(it)` 每轮重读

| 项 | 值 |
|---|---|
| 改前 | 16.48 ms |
| 改后 | 10.81 ms |
| 变化 | **-34.4%** |
| 对 C 比值（改前 → 改后） | 13.47× → **8.83×** |
| C 参考耗时 | 1.22 ms（`gcc -O2`，min of 5） |

**实测进寄存器的值**：`rbx`、`r15`（objdump 实测，热循环里承载变量值的 callee-saved 寄存器）

## 改动

| 文件 | 改了什么 |
|---|---|
| `bootstrap/qlmc/qlmc.qma` | 新增 `_depth_weight(d)`；`_alloc_vars` 的 `ucnt` 统计由 `+1` 计数改为按 `4^depth` 加权 |

这是**一处**编译器改动同时惠及 21 个基准中的本项，不是本项专属的代码路径。

## 已知边界 / 遗留

- 权重 `4^depth` 是经验值，未做代价模型（溢出代价 vs 寄存器压力）。
  同一处改动也让 3 项变慢，最显著的 `b15_loopsum` **+31%** 记为待查项
  （试过循环头对齐，无效已撤回；怀疑 L2 组相联冲突但无计数器证据，不猜）。
- 矩阵类基准的 `r*n`/`k*n` 仍每轮重算 —— 需 LICM，而 LICM 因缺别名分析
  被撤回（见 `docs/07-gaps.md` §5）。
