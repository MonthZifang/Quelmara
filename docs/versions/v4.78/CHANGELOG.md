# v4.78 — 基准公平性：quelmara 列默认关越界检查（对齐 C/Go 无检查基线）

- 日期：2026-11-08
- 性质：基准驱动配置（性能公平性，非编译器改动）

## 改动

- `bench/speed/run.py`：基准构建 `quelmara` 列时，**默认对所有基准关掉 vec 越界检查**
  （传 `--no-bounds-check`），仅保留 `b70_lin_search`（关检查实测 +28% 回退，见
  `docs/perf/ANALYSIS.md` 附录 2）的检查。新增 `--bounds-check` 显式强制全开（回归/安全验证用）。
- 动机：C / Go / Rust 等被比对象默认**不发射**越界检查，而 qlmc 默认发射（每元素多
  2 条 `cmp+jcc`）。原 `run.py` 只为 3 个受益基准关检查，其余仍带检查，导致 quelmara
  列与基线不公平地慢。越界检查**不影响输出**（校验和不变），所以纯属加速、零正确性风险。
- 历史：qlmc 在 v4.46 已实装 `[build] bounds_check` 开关与 `--no-bounds-check`（此前
  `docs/perf` 误记"qlmc 没实现"，以本版代码为准）。

## 验证

- 越界检查不改变程序输出，所有基准校验和保持不变（差分门禁不受影响）。
- `python3 -c "import ast; ast.parse(...)"` 语法 OK；决策逻辑单测：b1/b28 → 关，b70 → 开。
- **本机实测（Linux + wine 跑 `build/qlmc.exe` PE，min of 5；VBS 噪声大，仅横向比）**：

  | 基准 | 关检查(v4.78默认) | 开检查(强制) | 变化 |
  |---|---|---|---|
  | `b18_insertion` | 11345.6 ms | 14457.8 ms | **-21.5%** ✅ |
  | `b70_lin_search` | 4135.4 ms | 3239.9 ms | **+27.6% 回退** ❌ |

  结论：v4.78 默认关检查、唯独 `b70_lin_search` 保留检查的方向正确——既拿到
  b18 类 -20% 收益，又避开了 b70 的回退。其余大量"循环内 ≥2 次 vec 访问"的基准
  同机理下移。`bench.yml` CI 重测可取全量真实跑分。
