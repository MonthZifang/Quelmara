## 0. 一句话结论

2.x 线把 Quelmara 从"**有一门自研语言和一堆能跑的库**"推到了
"**有一条自举闭环的编译器 + 一套在 CI 上可复现的性能证据**"。

| # | 事件 | 版本 | 为什么重要 |

| 2 | **基准搬到 GitHub CI** | v2.54 | 跑分从"本机噪声里的读数"变成"可复核的权威数字" |
| 3 | **性能进入 C/Go 射程** | v2.46 → v2.79 | "能与高性能语言对比"从口号变成表格 |

## 2. 阶段一：补库与运行时下沉（v2.01 – v2.12）

这 12 个版本把 `07-gaps.md` §2「标准库」的 ❌/🟡 逐行刷绿，并做了一件关键的事：
**把服务端运行时从 Python 搬进本语言**。

| 版本 | 交付 | 性质 |
|---|---|---|
| v2.01 | `std/kv` 批量提交，写路径 **6.1×** | 性能 + 持久化 |
| v2.02 | URL/JSON/KV 解析路径批量提速 | 性能 |
| v2.03 | `std/log` + `std/logfile`（时间戳 / 轮转） | 库补齐 |
| v2.05 | `std/ds` 公开模块（RingBuf / MinHeap） | 库补齐 |
| v2.07 | IPv6 TCP 全链路 + 双栈监听 | 库补齐 |
| v2.08 | `std/timer` 重写（轮询式） | 库补齐 |
| v2.10 | HTTP 路由表 + 中间件链 | 库补齐 |
| v2.11 | `.qla` 目标文件（函数级增量 + 二进制库） | 工具链 |
| v2.12 | **IOCP reactor 搬进 `std/net/reactor.qma`** | **运行时自举** |

**v2.12 是这一阶段的分水岭**：v1.4 起手搓的 400 行 Python IR（`__net_serve` /

（Win64 线程入口 ABI）与 `net_config`（编译期读 `[net]`）。事后看，这是
"服务端链路 100% 本语言"这句主张的**实际兑现点**，也是后续自举的心理准备。

## 3. 阶段二：自举（v2.13 – v2.44）

这是 99 次更新里**最长、最硬、最有价值**的一段：31 个版本，从"启动时先起 Python"
走到"编译器编出自己且不动点成立"。

### 3.1 子集推进表（S1 → S20）

自举不是"重写一遍编译器"，而是**一块一块地把语言特性搬进 qlmc**，
每搬一块就用 stage-0 做逐字节差分对拍。子集推进顺序如下：

| 子集 | 版本 | 新增能力 |
|---|---|---|
| S1 | v2.14 | `.qma` → PE32+ 全链路（int/bool/print/let/while/if） |
| S2 | v2.15 | `str` / `const` / `assert` |
| S3 | v2.17 | `struct` / 定长数组 / `for` / `break` / `continue` |
| S4 | v2.18 | `enum` / `match`（顺带揪出 stage-0 结构体尺寸误编译） |
| S5–S6 | v2.19–v2.20 | `vec` / 聚合形参与返回值（ABI） |
| S7–S8 | v2.21–v2.22 | `map` / 切片 `[]T` |
| S9–S12 | v2.23–v2.26 | `defer` / `import` / `@ffi` / 闭包 |
| S13–S16 | v2.27–v2.30 | vec 扩容 / 位运算与进制字面量 / 不定参 / `const` 求值 |
| S17–S18 | v2.31–v2.32 | `vec[Struct]` + `else if` / `spawn`·`join` 真线程 |
| S19 | **v2.33** | 内存与串内建 + import 向上查找 → **qlmc 编出了自己** |
| S20 | v2.38 | f64（数值部分） |

### 3.2 三个关键瞬间

**① v2.33 — qlmc 编出了自己**

内存/串内建 + import 源根补齐后，`qlmc` 第一次编译自己的源码，产出 stage-2。
这一步之前的所有子集推进都是"准备"，这一步之后才有"闭环"。

**② v2.35 — 不动点成立（stage-2 == stage-3）**

stage-2 再编自己得到 stage-3，两者**逐字节相同**。这是自举的数学判据：
编译器已经能完整、稳定地描述自身。修的是工作区大小与堆越界检查两个问题。

**③ v2.44 — 优化层（Quelmara 写的 IR pass）**

此前 qlmc 没有任何 pass，源码注释也写着"没有 CSE/调度/内联，IR 只是多一层搬运"。
v2.44 在「降级之后、分配之前」加了三条 pass（常量折叠 / DCE / 标记），
并顺带把帧改成按需分配，修掉两个栈溢出。

### 3.3 自举线上的教训

自举过程中发现的一类缺陷值得单列：**stage-0 与 qlmc 的分歧，往往先是 stage-0 错**。

- v2.18 的 `enum` 推进揪出 stage-0 的**结构体尺寸误编译**；
- v2.37 定性：报错路径的崩溃是 **stage-0 的缺陷**，qlmc 自己的后端是对的；
- v2.41 发现"map 不扩容"是**与 stage-0 的真分歧**。

差分对拍的价值正在这里：两个独立实现互为裁判，谁错不由谁自己说了算。

## 4. 阶段三：性能攻坚（v2.45 – v2.79）

### 4.1 从 4.28× 到 1.00×：b2_float 的四级跳

`b2_float` 是整条 2.x 线上**单点收益最大**的一项，也最能说明"性能问题常常不在
你以为的那一层"：

| 版本 | qlmc | C | qlmc / C | 主循环指令数 | 改了什么 |
|---|---|---|---|---|---|
| v2.54 | 59.5 | 7.0 | **8.5×** | 52（含 `call __memcpy`） | 起点 |
| v2.55 | 19.6 | 4.9 | 4.0× | 12 | f64 进 XMM（标量化） |
| v2.56 | 6.3 | 6.5 | 0.97× | 8 | 打破 SSE 假依赖 + 常量槽 |
| **v2.57** | **4.7** | **4.7** | **1.00×** | 8 | 条件跳转立即数 + 循环临时值进 callee-saved |
| v2.65 | — | — | **0.87×（反超）** | 15 | f64 独立 XMM 寄存器文件 |

v2.65 的两个坑（写进了 CHANGELOG，也值得在这里复述）：

1. `fx` 少一条 `movaps` → **静默算成 0**（不是崩溃）。夹具用"循环累加 vs 直线展开
   两条路径对拍"才抓到。
2. `@simd` 的 `vsumd`/`vdotd` 把 xmm0/xmm1 写死当临时 → 与 XMM 池冲突。
   处置是"含 SIMD 归约的函数整体放弃 XMM 分配"。

### 4.2 其余关键优化

| 版本 | 改动 | 效果 |
|---|---|---|
| v2.48 | 常数除法魔数乘法 | `b1_int` **4.8×** |
| v2.47 | f64 字面量只解析一次 | `b2_float` **11.5×** |
| v2.49 | `&&`/`\|\|` 短路直接发跳转 | `b9_json` **1.54×**，体积 −8.9% |
| v2.50 | 变量寄存器按使用次数分配 | `b7_sort` **19%** |
| v2.64 | int→str 取位循环不用 `idiv` | `b5_string` **2.2×** |
| v2.66 | 越界检查收成一条无符号比较 | 每次下标省 2 条指令 + 1 个分支 |
| v2.76 | 堆从 `.bss` 换 `VirtualAlloc` 私有页 | `b4_array` **−54%**（根因是页错误，不是循环） |
| v2.93 | 内联阈值 28→60 | `b8s4 −37%` / `b5 −21%` / `b9 −15%` |
| v2.96 | `__vec_grow` 禁止内联 | 收掉 v2.93 的代价：`b4 −20%` |

### 4.3 v2.96 的教训：元凶是"一个具体函数"，不是"阈值太宽"

v2.93 放宽内联阈值拿到大收益，代价是 `b4_array` **+23%**。当时的归因是
"阈值 60 太宽"，但真正的元凶是**一个函数**：`__vec_grow`（含 realloc + memcpy
搬旧数据的冷路径 helper）被内联进了 push 热循环。

给它打 `no_inline=True` 就解决了。**需要的不是按热度分档的启发式引擎，
而是按冷热路径分档的一个标记**（`07-gaps.md` §5 已登记这个判断）。

### 4.4 负结果也是交付物

99 次更新里有相当一部分是**明确证伪并回滚**的实验。它们没有留在代码里，
但留在了文档里，避免后人重走：

| 版本 | 实验 | 结论 |
|---|---|---|
| v2.02 | SHA-256 8 轮展开 | 无收益（瓶颈是指令数不是搬移） |
| v2.60 | 无帧函数（省 `push rbp`） | 无收益（瓶颈是调用延迟链） |
| v2.60 | `vec.push` 容量检查内联 | 无收益（内存带宽瓶颈） |
| v2.88 | 无分支回绕 | **负结果：b1 慢 6.6×**，已回滚 |
| v2.89 | b8 的微优化 | 测不出来（本机分辨率只到 ±20%） |
| v1.98/v2.x | chan 抢锁先自旋 | 无可复现收益，回滚 |

> **两条性能铁律**（两次回滚换来，见 `07-gaps.md` §5 末尾）：
> 1. 单点核对全对 ≠ 装起来对——必须反汇编对照或单元素 trace。
> 2. 前置条件不满足就回滚并登记重启条件；错误代码比没有代码更糟。

### 4.5 性能终态（CI 权威数字）

10 项基准（来源见 `06-status.md`，此处只列结论）：

| 分档 | 基准 | 对 C |
|---|---|---|
| **不慢于 C** | `b2_float` / `b5_string` / `b6_hash` | **1.00× / 0.78× / 0.99×** |
| 1.1–1.5× | `b7_sort` / `b8_threads4` | 1.33× / 1.45× |
| 2–3× | `b3_recursion` / `b4_array` | 2.00× / 2.85× |
| 3.8–4.3× | `b9_json` / `b1_int` / `b8_threads1` | 3.82× / 4.28× / 4.28× |

**为什么 b1/b8 追不上**：C 的版本被**完全向量化**——`zig cc -O2` 编
`acc += (i*7)%13` 生成的是 48 条 AVX2 指令的循环，一次算 16 个元素。
这不是调用开销或寄存器分配能弥补的差距，需要真正的自动向量化器
（`07-gaps.md` §5 已登记，前置条件包含"本机无 AVX2，需先写 mini-emulator 验语义"）。

## 5. 阶段四：第二条执行通道与收口（v2.80 – v2.99）

### 5.1 这一段做了什么

| 版本 | 交付 |
|---|---|
| v2.80–v2.84 | **解释器 `qlm_interp`**（用 Quelmara 写）：子集逐步补齐至闭包 |
| v2.85–v2.86 | qlmc 缺陷修复 + 复合赋值 |

| v2.93–v2.96 | 内联调优 A/B（含 v2.96 的代价收口） |
| v2.97–v2.99 | **TLS 根证书库 + P-384/SHA-384**（根库自验证 5/12 → 11/12） |

**解释器**（v2.80）值得单独提：它给语言加了第二条执行通道。这不是性能优化，
而是**可用性**——不编译直接跑 `.qma`，脚本化与调试路径都变短了。

### 5.2 编号空位说明（v2.04 / v2.06 / v2.09）

三个目录不存在，**不是丢失**：

- **v2.04**：在代码注释里被预占，任务最终被 v2.03 吸收；
- **v2.06 / v2.09**：由同期并行轨落地后并入相邻版本。

原始记录在 `docs/versions/v2.05/CHANGELOG.md` 的「已知边界」一节。
因此 2.x 线是 **99 次编号更新 / 97 个版本目录**——这两个数不一样，
引用时别混用。

### 5.3 分类口径

§1.2 的主题分类由脚本按 **CHANGELOG 标题 + `影响面` 行**做关键词匹配得出
（自举/qlmc/bootstrap、编译器/后端/IR、性能/快/倍、标准库/std/、工具链/CI 等）。
它是一张**导航图，不是审计报表**：一条更新命中多个主题时会计入多列，
个别归类可能把"顺带修了个 bug"算进主主题。准确归类以各版本 CHANGELOG 正文为准。

### 5.4 v2.97–v2.99 的一条方法论

v2.99 修 P-384 时踩了一个值得记住的坑：t161 第一版把 **Root YE 当信任锚**，
链验证失败，于是花了几轮排查 TBS 提取、公钥点编码、DER 偏移，最后用 openssl +
独立 Python 实现双向确认"输入的每个字节都对、P-384 验签本身也对"。

真相是**链构造错了**：`Root YE` 由 `ISRG Root X2` 签发，它自己不是自签根。

> 教训：验证失败时**先怀疑输入**再怀疑算法。区别在于"我构造的测试数据是否
> 符合协议"可以被外部工具独立裁判，而"我的实现是否有 bug"不能自证。

## 6. 这 99 次更新没做到的事

诚实记账比成绩单更重要。以下都是**明确未做**，不是"以后再说"：

| 缺口 | 状态 | 为什么 |
|---|---|---|
| 自动向量化器 | ❌ | b1/b8 卡在这里；需先有 AVX2 语义验证环境 |
| macOS Mach-O + kqueue | ❌ | 新后端 + 新事件层；连带后果是 CI 基准矩阵缺那一列 |
| wasm32/64、Android | ❌ | 新后端 + 线性内存模型 |
| SHA-NI 加速 | 🚧 | 基础设施已就绪，但**本机 CPU 无该扩展**，需先写 mini-emulator |
| futex / WaitOnAddress park | 🚧 | 唤醒延迟 25 ms → µs 需新 syscall 路径 + 防唤醒丢失 |
| OCSP / CRL 吊销检查 | ❌ | 独立子系统，不塞进曲线补丁 |
| 通用循环向量化 / 跨档案内联 | ❌ | 见 `07-gaps.md` §5 |

## 7. 复盘：什么起了作用，什么没有

### 7.1 起作用的做法

1. **差分对拍互为裁判**。stage-0 与 qlmc 两套独立实现比对，谁错不由谁自己说了算。
   自举线上揪出的 stage-0 缺陷（v2.18 / v2.37 / v2.41）全靠这个。
2. **基准搬到 CI**（v2.54）。本机噪声 ±40–50%，`min-of-N` 也只压到 ±20%；
   干净 runner 才让"改完到底快了没有"变成可判定问题。
3. **负结果入库**。v2.88 的无分支回绕慢 6.6×、v2.60 的无帧函数无收益——
   写进文档而不是删掉，直接避免了重复实验。
4. **数字单一来源**（`06-status.md`）。此前同一指标在四份文档里是
   96/113/116/124，门禁只查短语不查数字，全部放行。这条规则是被事故逼出来的。
5. **一次任务一个版本目录**。99 次更新 = 97 份可独立检索的记录，
   复盘时能精确回到"当时为什么这么改"。

### 7.2 走过的弯路

1. **先改再看**。v2.60 的越界检查"声称做过但没进提交"（做 A/B 的脚本最后一轮
   把源码留在了 `off` 状态），v2.66 重新实现并量过。教训：**A/B 脚本必须
   把工作区状态打印出来**。
2. **归因过早**。v2.93 把 b4 的 +23% 归因于"阈值太宽"，真相是一个具体函数
   （v2.96）。笼统归因会导向建一个不需要的启发式引擎。
3. **怀疑算法先于怀疑输入**（v2.99 的 Root YE）。外部工具能裁判输入，
   不能自证实现。
4. **测量分辨率没先确认**。v2.89 才发现本机分辨率只到 ±20%，
   之前几轮"微优化"的数字都在噪声里。

### 7.3 一句话带走的经验

> **能被外部工具裁判的，先裁判；不能自证的，别急着归因。**

---

## 8. 下一步（v3.x 方向）

按 `07-gaps.md` §5/§6 的排序，优先级最高的是**收益可证、前置已就绪**的两项：

1. **SHA-NI**：SHA-256 65 ms → ~3 ms 量级（20×）。前置是 mini-emulator 验证
   8 条 xmm 指令语义——"错 hash 比慢更糟"。
2. **futex / WaitOnAddress**：把 `wg_wait` 唤醒延迟从 25 ms 降到 µs 级，
   且 CPU 仍归零。
3. **寄存器池扩到 11**：b9_json 的 jval 有 198 vreg / 24 溢出槽，
   caller-saved 现在只用 4 个。前置是先审计 `idiv`（RDX:RAX）、变量移位（CL）、
   `cpuid`（四寄存器全占）的隐式使用。
4. **macOS 后端**：补上 CI 基准矩阵缺失的那一列。
