## 改动：常数除法 / 取模 → 无符号魔数乘法

stage-0 的 `('bin','div'/'mod', d, a, ('imm',C))` 一直是 `idiv`
（20-40 周期、微码化）。新增 `opt_const_div`，对 **`analyze_nonneg` 能证明
`a >= 0`** 的位置换成魔数乘法：

* `M` 装得进 64 位（d=10/13）：`umulhi + shr`（2 条）
* `M` 装不进（d=7/1000）：libdivide 修正式
  `t = umulhi(n, M-2^64); q = (t + ((n-t)>>1)) >> (s-1)`（5 条）
* 取模再补 `imul + sub`

算法用 Granlund-Montgomery 的充分条件 `2^(64+s) <= M*d <= 2^(64+s) + 2^s`。
自校验：`d=13` 算出的 `(5675921253449092805, 2)` 与 `opt_mod_inductive`
手写在 `b1_int` 里的魔数**完全一致**。

**只做非负**：有符号魔数除法要多 3 条符号修正链，且负数的 floor 语义
容易写错；非负覆盖了转字符串、取模索引、哈希这些主要场景。

**位置**：排在 `opt_mod_inductive` **之后** —— 归纳削减靠 `('bin','mod')`
的形态匹配，先转成魔数就再也匹配不上。

**回归**：`tests/t146_const_div.qma`。校验口径是
`q*C + r == a` **且** `0 <= r < C`（两条合起来才唯一确定 q = floor(a/C)；
只测等式会把"q 少 1、r 多 C"也算对）。覆盖 0..3999 × {3,7,10,13,1000}、
2^31-1 / 2^32 / 2^40 / 2^50 边界、以及"a 增加 C 时商恰好 +1"的平移性质。

**诚实结论**：本机基准**测不出收益**。原因很具体 —— `analyze_nonneg`
要求归纳变量有**常量上界**，而 `__str_from_i64` 的循环上界是运行期值，
`a in nn` 过不了，`div 10` 仍然是 `idiv`（反汇编确认 b5 里还有 10 处）。
下一步要么加强 `analyze_nonneg`（区间传播到运行期上界），要么把
"转字符串的除数恒为 10"这种**常量除数 + 已知符号**的场景单独认。

## 试过但回退的（有数据）

| 改动 | 结果 |
|---|---|
| **拷贝合并**（`mov d,s` 让 d 继承 s 的寄存器） | b1 循环 15→11 条，但**全量回归 30+ 用例误编译**（sha256/x25519/utf8/regex…）。根因：合并打破了发射器 `safe_dst_reg(dst,[a,b])` 的假设，放宽后仍有未覆盖的指令形态。**整段回退** |
| **循环旋转**（guard 复制到循环尾） | b1 循环 15→9 条、taken 分支 2→1，**时间完全不变**（仍 38 ms，因为测的是 qlmc）。用 stage-0 重测时发现**b9 段错误**（回边改 `jcc` 后 CFG 对若干 pass 隐身），回退 |
| **`opt_strlen_hoist` 认内联长度前缀** | 目标是让 `opt_bounds_elim` 能证明"hi 在循环内不变"从而删掉每次下标的越界检查。两次实现都让 b9 段错误（`p` 的定义不在循环头的支配路径上），回退 |
| **无帧函数 / push 容量检查 / 内联阈值 48 / fail 不内联** | 前三个无收益（详见 v2.60 CHANGELOG）；fail 不内联是**体积**收益（−16%），保留 |

## 保留的一处防御性改动

`loop_regions` 现在同时认 `jmp L` 与 `jcc cc,a,b,L` 两种回边。循环旋转
（若将来重做）会把回边变成条件跳转，不认 `jcc` 的 pass 会对旋转后的循环
隐身 —— 这正是上面那次 b9 段错误的成因之一。
