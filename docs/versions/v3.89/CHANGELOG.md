# v3.89 — 修 `ndef` 重复累加（`_opt_copy` 的判据一直被它卡死）

- 日期：2026-11-02
- 任务：查 §7.31 里 `b1_int` 1.48× 的"分配器多一次寄存器复制"。
- 结论：**不是分配器的问题**，是 `_opt_ndef` 被调用了两次而中间没清零。
- 影响面：`bootstrap/qlmc/qlmc.qma`（`_opt` 末尾加 6 行清零）、
  `docs/07-gaps.md`（§7.31 记负结果）、`docs/06-status.md`（§3.127）

## 缺陷本身

`_opt` 在归纳削减（`_opt_mod_ind`）之后要重算 `use`/`ndef`，再跑一次
`_opt_copy` + `_opt_dce`。但那段代码**只清了 `use`，没清 `ndef`**：

```quelmara
_opt_mod_ind(fc, cok, cval, use, ndef)
_opt_ndef(ir, ndef)          // ← 累加语义，第二次调用把每个计数又加一遍
i = 0
while i < len(use) { use.set(i, 0); i = i + 1 }   // ← use 清了，ndef 没清
```

`_opt_ndef` 是 `ndef.set(dst, ndef.get(dst) + 1)`，**累加**。所以第二次调用后
每个 vreg 的定义次数都翻倍，`_opt_copy` 的 `ndef.get(d) == 1` 条件永远不成立 ——
**归纳削减插的那条 `MOV dst, v` 一条也消不掉**。

`b1_int` 的热循环里就白留一条 `mov r8, r6`：

```asm
mov  r8, r6          ← 多余的复制（v3.83 记成"分配器多出来的一次复制"）
add  r12, r8         ← 应为 add r12, r6
```

修完变成：

```asm
add  r12, rsi        ← 直接用计数器
```

## 为什么 v3.83 没找到

v3.83 把它归因为"分配器在加法点和自增点给同一个 vreg 用了不同寄存器"，
方向就错了 —— IR 层看，`MOV 23, 47` 是**显式的一条指令**，不是分配器
临时产生的。当时的尝试（复用 `dst` 当计数器）是在发射层绕，自然没效果。

**教训**：看到"多一条 `mov`"，先确认它在 **IR 里存不存在**；IR 里就有的话，
那是某个 pass 该消而没消掉的，不该去发射器/分配器里找。

## 但性能没有改善 —— 又是一次负结果

| 基准 | stage-0 | v3.88 | v3.89 | 比值 |
|---|---|---|---|---|
| `b1_int` | 65.7 ms | 97.3 ms | 98.0 ms | **1.49×**（无变化） |
| `b9_json` | 76.8 ms | 98.4 ms | 98.2 ms | 1.28×（无变化） |
| `b2_float` | 101.9 ms | 81.8 ms | 81.3 ms | 0.80× |
| `b7_sort` | 98.4 ms | 56.6 ms | 56.6 ms | 0.58× |

（公平对比：两边都是 PE + wine，5 次取最小。）

**为什么没快**：反汇编确认循环体已经是 7 条指令，和 stage-0 结构相同，
但**条件减仍然用 `jl` 分支**：

```asm
cmp  $0xd,%rsi
jl   0x140001b0d
sub  $0xd,%rsi
jmp  0x140001aeb
```

stage-0 用的是 `cmovns`（无分支）。这是 **v2.88 有意保留的**：
无分支版要多两个临时值，`b1_int` 的寄存器池不够会溢出，实测慢 6.6 倍。

所以 `b1_int` 的 1.48× 剩下那部分**就是这条分支**，与 MOV 无关。
v3.83 那条"要收掉得改分配器"的判断方向对，但具体到 `b1_int`，
真正的卡点是**寄存器压力**（无分支版需要更多临时值），不是"多一次复制"。

## 保留这个修复的理由

**它修的是一个真 bug**（`_opt_copy` 的判据被卡死），不是"为了性能硬凑"：

* 归纳削减的收益在别的形状上仍然存在（`b9_json` 的 `jnum` 等）；
* 这条 `MOV` 消除对所有走 `_opt_mod_ind` 的循环都生效；
* 代码体积 +512 字节（重排导致），可接受；
* 全部回归通过：`tests/qlmc_test.py` 104/104、覆盖率 69/69。

**但它不是性能优化**，所以不记成"收掉 §7.31 的一部分"，只记成缺陷修复。
`b1_int` 的下一步是**寄存器压力**方向（让无分支条件减在小函数上也放得下），
那才是 §7.31 (a) 真正的卡点。
