# v2.53 — 越界检查"取长度 + 比较"融合（`cmp r64, [base±8]`）

- 日期：2026-10-25
- 任务：严重优化性能与加速比
- 影响面：自举层（两个新操作码 + `_vec_check` / 字符串下标）

## 做了什么

`vec.get(i)` / `s[p]` 的越界检查原来是两条：

```
mov  r9, [h + 8]        ; 先把长度装进寄存器
cmp  i, r9
jb   ok
```

`cmp` 本来就支持内存操作数，所以可以合成一条：

```
cmp  i, [h + 8]         ; 一条顶两条
jb   ok
```

新增两个操作码：

| 操作码 | 语义 |
|---|---|
| `OP_JCMPVLEN` | `cmp a, [b+8]; jcc → imm`（vec 头块的长度在 `+8`） |
| `OP_JCMPSTR` | `cmp a, [b-8]; jcc → imm`（`str` 的长度在 `-8`） |

`dst` 放 jcc 码、`a` 放左操作数、`b` 放句柄/字符串、`imm` 放目标标签 —— 正好用满
`Ir` 的四个槽。`_vec_check` 不再调 `_vec_field`，字符串下标那条 `OP_LEN` 也删了。

## 两个坑

**① `cmp` 的 opcode 用错了。** 第一版写 `0x39`：

- `0x39` 是 `cmp r/m64, r64` —— 算 `rm - reg`，发出来是 `cmp [rcx+8], rax`，
  也就是**长度 - 下标**；
- `0x3B` 才是 `cmp r64, r/m64` —— 算 `reg - rm`，`cmp rax, [rcx+8]`，**下标 - 长度**。

条件整个反过来了，表现是**在界内反而走 die 路径**（进程 exit 1，且不崩在栈上，
只是安静地退出）。

**② 同一个字符串在 `_opt_writes` 和 `_opt_pure` 里各出现一次**：
`if op == OP_LAB || op == OP_JMP || op == OP_JCMP { return 0 }`。
`str.replace(..., 1)` 只命中第一处（`_opt_writes`）。这次没出事 ——
因为 `_opt_pure` **默认返回 0**（不纯），新跳转不会被 DCE 删掉。但改这类
"两处同形"的代码要留意：**先数一遍这个字符串出现几次**。

## 剩下的三件大事（都是"新一层机器"，不是再加两条 peephole）

到这一版，`bench/speed` 的比值已经收敛到 **1.3×–3.8×**，剩下的差距都有明确的
单一原因，而且**每一件都需要一个 qlmc 现在没有的组件**：

1. **`b9_json` 3.9×** —— 主要是**函数调用开销**（`jws`/`jstr`/`jval` 每 token
   调一次，prologue + epilogue 约 14 条指令），C 会内联。需要**内联器**
   （IR 层拼接 + 变量重编号 + 标签重映射 + 长度变化后的 `vstart`/`vend` 重建）。
2. **`b2_float` 2.9×** —— f64 仍住帧槽，每次运算两次 `movsd` 内存往返。
   需要**第二个寄存器文件**（XMM）进分配器。
3. **`b4_array` 3.8×** —— 16 MB 数组，**内存带宽**。这个不是编译器能改的。

另有一件中等工程：**越界检查消除**（范围分析证明 `i < len`），能把 `b9_json` /
`b7_sort` 的每字节检查彻底去掉。
