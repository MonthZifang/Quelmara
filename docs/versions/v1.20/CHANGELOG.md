## 为什么是它

`docs/07-gaps.md` 的 P0 第 1 项是 TLS。TLS 1.3 的 ECDHE 默认曲线是 X25519，
而密码学零件里只差它（SHA-256+HMAC ✅、AES-128-GCM ✅、X25519 ❌）。
它还是纯计算、不需要网络，能用 RFC 7748 官方向量逐字节验证——风险最低、价值最高。

## 实现要点

- **不用 128 位乘**：64 位乘法的**位模式**是精确的（溢出只影响符号解释），
  所以 `lo = a*b & 0xFFFFFFFF`、`hi = (a*b >>> 32) & 0xFFFFFFFF` 都正确。
  这让 8×32 位 limb 的实现可以只用普通 `*` / `&` / `>>>`。
- **归约**：16 limb 乘积折 `2^256 ≡ 38` 三轮，再条件减 p 两次。
- **求逆**：平方-乘，指数 p−2（255 位），不需要优化过的 addition chain。
- **cswap**：掩码交换（`(a^b) & (0-bit)`），不按位分支。

### 调试实录（值得记）

第一版全错。逐层二分：小整数乘法 ✅ → 求逆 ✅ → 单步 ladder 的 x2/x3/z3 ✅ 但 **z2 差 38**。

根因在 `fe_sub`：先把 `2^256` 进位折成 `+38` 再相减。因为 `2p = 2^256 − 38`，
当 `a + 2p` 产生进位时折完恰好退化成 `a`，再减 b 就产生借位并回绕——结果恒定差 38。
修法：**先减后折**（保留第 9 个 limb，减完再折 `r[8] * 38`）。

第二个 bug 更简单：基点 9 按小端应该是**首字节** 9，我写成了末字节。

## 已知边界 / 遗留

- **不是严格常量时间**：`cswap` 是掩码实现，但 `fe_cond_sub` 的分支依赖数据
  （借位与否），理论上存在时序侧信道。用于对外 TLS 服务端前应评估或改为无分支写法。
- **性能**：7 ms/次，约为优化过的 C（OpenSSL ~0.05 ms）的 100 倍。
  瓶颈是每次域运算都分配 vec + 逐 limb 循环；优化方向是展开 fe_mul、复用缓冲。
  握手场景（1 次密钥生成 + 1 次共享 = 14 ms）可接受，批量密钥交换不合适。
- **只有 X25519**：无 X448、无 Ed25519（签名），无 RFC 7748 §5.2 的 1000/1000000 次
  迭代向量（耗时太长，未纳入回归）。
- TLS 还缺记录层、握手状态机、X.509 解析——下一轮的主线。
