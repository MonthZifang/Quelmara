# v2.86 — qlmc 支持复合赋值 `+= -= *= /= %=`

- 日期：2026-10-27
- 任务：qlmc 追平语言层（第 1 项）
- 影响面：`bootstrap/qlmc/qlmc.qma`（词法 + `_stmt`）、
  `tests/selfhost/s28_compound.qma`、`tests/qlmc_test.py`

## 为什么做这个

`examples/collatz.qma` 里有一句 `steps += 1`，qlmc 直接拒绝：

```
qlmc: line 11: 期望表达式
```

复合赋值是 stage-0 有、qlmc 没有的语言特性之一（和闭包、嵌套 struct 字段
同一类"自举还没追平"的缺口）。`collatz.qma` 是仓库自带的示例，编不过很难看。

## 改法

1. **词法**：`+ - * / %` 后面跟 `=` 时合成复合赋值记号（两字符优先）。
2. **语法**：`_stmt` 里解析完左值表达式后，若下一个记号是复合赋值，
   展开成 `lv = lv <op> rhs`，再按普通赋值走（变量 / 字段 / 下标三种左值都支持）。

左值会求值两次（`v[f()] += 1` 里 `f` 调两次）—— 变量与下标是幂等的，这种写法
在实际代码里几乎不出现，先按简单来。解释器那边是同一口径。

## 一个"静默错"的坑（花了很久）

第一版把新记号的 id 定成 **29..33**，因为"`P_FATARROW = 28` 是最后一个"。
结果：

| 新 id | 撞上 | 表现 |
|---|---|---|
| `P_PLUSEQ = 29` | （空） | **`+=` 正常** ← 唯一的幸存者，最迷惑人 |
| `P_MINUSEQ = 30` | `P_AMP`（`&`） | `z -= 3` 变成 `z & 3` 的表达式语句，**赋值静默消失** |
| `P_STAREQ = 31` | `P_PIPE`（`\|`） | 同上 |
| `P_SLASHEQ = 32` | `P_CARET`（`^`） | 同上 |
| `P_PERCENTEQ = 33` | `P_SHL`（`<<`） | 同上 |

**没有报错、没有崩溃，就是算错**（`a` 保持 10）。查的时候一路以为是
`_expr` 吞了记号，打了四轮调试输出才定位到：`_expr 前 pos=10 / 后 pos=13`
—— 表达式解析器吃掉了 3 个记号，因为 `_and_e`/`_or_e` 那几层把 30/31 当成了
位运算符。

**教训：那张标点表不连续**（`P_FATARROW=28` 之后直接跳到 `P_AMP=30`，
29 是空的）。加新 id 前必须把**整张表**看一遍，不能只看"最后一个"。现在的
复合赋值从 **37** 起，注释里写清了 30..36 被谁占着。

## 效果

- `examples/collatz.qma` 现在能被 qlmc 编译，输出与 stage-0 逐字节相同
  （`77031 / 350 / 111`）。
- 新夹具 `tests/selfhost/s28_compound.qma` 覆盖：五种运算符 × 三种左值
  （变量 / 定长数组下标 / struct 字段）+ collatz 形状的循环。
  下标只测**定长数组** —— stage-0 的 `v[i] = x` 不支持 vec，只支持数组/切片。
