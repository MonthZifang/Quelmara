# v4.102 — 查清"11 项集体退化"：不是代码回归，是 CI 换了机器

- 日期：2026-11-10
- 任务：核实"b3_recursion 3.3→8.5、b34_bitops 12.7→28.4…"这批退化
- 影响面：工具链（新增 `tools/dev/bench_trend.py`）、文档

## 结论先说：**没有性能回归**

那 11 项确实在 CI 上从"快"变成"慢"，但**不是我们的代码变慢了，
而是 v4.96 那一次 CI 恰好跑在了更快的机器上**。

## 证据

### 1. 用 C 归一化后，v4.92 与 HEAD 的比值几乎相同

| 基准 | v4.92 `quelmara/C` | HEAD `quelmara/C` | 判定 |
|---|---|---|---|
| `b3_recursion` | 3.54× | 3.54× | **持平** |
| `b34_bitops` | 6.95× | 6.95× | **持平** |
| `b35_branch` | 20.14× | 20.14× | **持平** |
| `b17_bubble` | 1.42× | 1.50× | 持平 |
| `b8_threads1` | 3.87× | 3.51× | 持平 |

### 2. C 的参照值暴露了机器差异

同一份 C 程序，三次 CI 的实测：

| 基准 | v4.92-C | **v4.96-C** | HEAD-C |
|---|---|---|---|
| `b3_recursion` | 2.4 | **2.2** | 2.4 |
| `b34_bitops` | 4.1 | **2.8** | 4.1 |
| `b17_bubble` | 6624.0 | **4582.4** | 6624.7 |
| `b8_threads1` | 50.7 | **33.2** | 51.0 |
| `b28_matrix` | 5.1 | **2.0** | 5.4 |

**C 自己就快了 1.45–2.7 倍**。既然 C 和 quelmara 跑在同一个 run、同一台机器上，
机器的快慢在"比值"里被约掉 —— 所以比值才是能跨 run 比较的量。

### 3. 本机二分验证：v4.96 → HEAD 的 5 个提交**零影响**

在本机逐个提交重编译 qlmc，实测同一批基准：

| 基准 | v4.96 编译器 | HEAD 编译器 |
|---|---|---|
| `b34_bitops` | 150 ms | 151 ms |
| `b3_recursion` | 29 ms | 29 ms |
| `b35_branch` | 85 ms | 83 ms |
| `b81_bit_reverse` | 111 ms | 111 ms |

产物指令数也只差 9–19 条（`cores()` 例程 = 105 字节，整体位移，热循环不变）。

## 新增：`tools/dev/bench_trend.py`

把上面这套分析固化成工具，避免下次再误判。

```bash
python tools/dev/bench_trend.py --sha a8f62a8 --sha b08a355 --sha 3d9bb01 \
    --only b3_recursion b34_bitops
```

输出（单元格是 `quelmara / C` 比值，越小越好）：

```
bench                      a8f62a8         b08a355         3d9bb01   判定
--------------------------------------------------------------------------
b3_recursion                 3.54x           1.50x           3.54x   持平
b34_bitops                   6.95x           4.54x           6.95x   持平
b35_branch                  20.14x           9.29x          20.14x   持平
```

**判定规则**（写进脚本）：

- 比值变化 < ±10% → 持平（CI 噪声）
- 同时打印 **C 列自身的变化**：若 C 变了 >20%，说明换了机器，
  那一次的数据**不可**用于跨 run 比较

## 教训

我在上一轮也曾误判过一次：把"性能回退"和"丢弃未提交实验"混为一谈。
这次又遇到同类问题 —— **CI 的绝对值不能跨 run 直接比**。

`docs/06-status.md` 里其实早就写着"跨 run 的绝对值不可比"（v2.58 的注记），
但那条只针对 Windows 本机 VBS 噪声，**没有覆盖 CI runner 机型漂移**。
本版把这条口径固化进工具，不再靠人记。

## 验证

## 已知边界 / 遗留

- `bench_trend.py` 依赖 `gh` 已登录且对应 run 的 artifact 还在（GitHub
  默认保留 90 天）。
- 只读 `bench-windows` artifact（`quelmara` 列只在 windows job 里有 ——
  posix job 上 `build/qlmc.exe` 不存在，`quelmara` 列直接跳过）。
- 没有做统计显著性检验，只做"比值 + C 漂移"两个判据。
