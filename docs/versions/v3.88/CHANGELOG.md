- 日期：2026-11-02
- 任务：v3.84 试过"标志位循环 → break"失败并回退，当时留下的下一步是
  "先建差分夹具再动手"。夹具（`s47_flagloop.qma`）v3.87 已入库并登记，
  这一版按那个前提重做。
- 影响面：`bootstrap/qlmc/qlmc.qma`（新增 `_opt_flag_loop`，239 行）、
  `docs/07-gaps.md`（§7.31 记正向结果）、`docs/06-status.md`（§3.126）
- 产物：`b9_json` **1.41× → 1.28×**（公平对比，两边都是 PE + wine）

## 为什么值得做

`b9_json` 的 `jws` / `jstr` 是同一个形状：

```quelmara
let mut go = 1
while go == 1 && p < n {
    if <空白> { p = p + 1 } else { go = 0 }
}
```

stage-0 把 `go = 0` 直接编成"跳到循环出口"；qlmc 保留
`CONST go,0` + `JMP 循环头` + 循环头的 `JCMPI go,1` —— **每处理一个字符
白跑一条 `cmp` + 一条 `jcc`**。

## v3.84 为什么失败，这一版怎么补

v3.84 只做了**局部模式匹配**（"找到 `CONST flag,0` 就把后面的 JMP 改跳出口"），
没验证"循环外还有没有读者"，结果校验和从 `4010000` 变成 `6000`（提前退出）。

这一版是**全函数扫描**的六条判据（见 `_opt_flag_loop` 的文档注释）：
进循环时 flag 必为 1 / 体内只有置 0 点写 / 体内只有守卫读 / 出口在回边之后 /
每个置 0 点后紧跟回边 / 循环头只有一条入边。六条全过才动手。

## 踩到的坑：不能改共享回边

第一版把 `CONST flag,0` 后面那条 `JMP ltop` **改目标**成 `lexit`。
`jws` 上看起来完全正确（IR 里守卫变 NOP、回边跳出口），但 s47 立刻翻红：

| 用例 | stage-0 | 第一版 |
|---|---|---|
| `scan_ws("   abc", 0)` | `3` | **`1`** ❌ |
| `scan_ws("     ", 0)` | `5` | **`1`** ❌ |
| `scan_and_report("abcXdef")` | `203` | **`103`** ❌ |

**根因**：`if c == 32 { p = p + 1 } else { go = 0 }` 的两个分支先汇合到
同一个 LAB，再**共用同一条回边**。改那条回边等于让 `p = p + 1` 也跳出循环。

**改法**：不动回边，在**每个置 0 点之后插入**一条专属的 `JMP lexit`
（从后往前插，避免下标漂移）。置 0 的路径被截住，其它路径照旧回循环头。

这正是 v3.84 记下的那条教训的延伸：**控制流变换不能只靠局部模式匹配，
"这条指令是不是只服务于我要改的那条路径"必须显式验证。**
s47 夹具在第一次跑就抓到了它 —— 夹具的价值当场兑现。

## 一个被排除的假线索

改完 pass 后 stage-2 编自己（stage-3）栈溢出，一度以为是这个 pass 的
O(n²) 重扫造成的。做了对照实验后否定：

```
build/s2_base.exe（HEAD，不含本 pass）  build qlmc.qma -j1  -> EXIT=1 栈溢出
build/qlmc_new.exe（HEAD）              build qlmc.qma -j1  -> EXIT=0 正常
```

也就是说 **stage-3 编自己本来就是 wine 下的已知限制** ——
`tests/bootstrap_test.py` 的文档里写着"第 3 级目前还不过，脚本把它当信息项
报出来，不判失败"，从 v2.34 起就是这样。与本 pass 无关。
（不动点由 CI 在 Windows 原生上验证，那是另一条路径。）
