# v3.01 — 循环旋转：负结果（b1 无收益，b9 崩），已回退

- 日期：2026-10-29
- 任务：性能 —— 试做 while → do-while 旋转，消掉每轮的无条件 `jmp`
- 影响面：无（**代码已回退**）；文档登记负结果

## 动机：b1_int 热循环每轮有 2 个分支

反汇编 `b1_int`（自研 ELF 后端）的主循环：

```
400129:  cmp $0x1312d00,%rsi        ; i < 20000000
400130:  jge 400154                 ; ← 守卫分支
400136:  mov %r8,%rdi
400139:  add $0x7,%r8
40013d:  mov %r8,%rax
400140:  sub $0xd,%rax
400144:  cmovns %rax,%r8            ; (i*7)%13 已削减成条件移动
400148:  add %rdi,%rbx
40014b:  add $0x1,%rsi
40014f:  jmp 400129                 ; ← 回边（无条件）
```

9 条指令、**2 个分支**。`jmp` 那一条理论上可以被"底部条件跳转"吸收，
于是每轮只剩 1 个分支。这是教科书里的 loop rotation，看起来是纯赚。

## 实现

按「守卫留头部 + body 加标签 + 底部反转条件回跳」写 `opt_loop_rotate`，
接在 `opt_invert_branch` 之后（反转才产生规范形态）。前提检查两条：

1. 守卫是紧跟循环头 label 的 `jcc`，目标是出口标签；
2. 回边是紧邻出口标签的 `jmp head`，且循环体内**没有其它跳回 head 的指令**
   （排除 `continue` 造成的多回边）。

## 第一版写错了布局，第二版形状对了

第一版把 `body_lab` 放在**出口标签之后**，于是底部 `jcc` 成立时跳到出口
后面的地址，循环体被跳过、跑成 0 次。反汇编一眼看出来：

```
400156:  jl 40015c      ; ← 目标竟是出口标签本身
40015c:  (程序其余部分)
```

改成正确布局后形状对了：

```
400136:  mov %r8,%rdi
...
40014f:  cmp $0x1312d00,%rsi
400156:  jl 400136      ; ← 底部条件回跳，body 落点正确
40015c:  (出口)
```

每轮确实只剩 1 个分支，`jmp` 消失。**形状验证通过。**

## 但是：b9_json 崩了

同一份源码，只开/关这一个 pass：

| 基准 | 关旋转 | 开旋转 |
|---|---|---|
| b1_int | 65.2 / 66.1 / 65.4 / 65.2 / 65.1 ms | 84.0 / 68.6 / 67.9 / 68.5 / 87.0 ms |
| b3_recursion | 正常 | 正常 |
| b4_array | 正常 | 正常 |
| b7_sort | 正常 | 正常 |
| **b9_json** | **4010000（正常）** | **`vec index out of bounds` 崩** |

（容器内各 5 次，C 参照同轮 86.3–86.7 ms。）

b1 的旋转版中位数 68.5 vs 未旋转 65.2 —— **没有收益**，且在噪声范围内偏慢。
b9 则是**正确性崩溃**。

## 结论：回退，并登记"前提不够"

两个前提（单回边 + 守卫在头部）都检查了，b9 仍然崩。根因是**前提不够**：

> b9 的循环体里有 `break` 跳出。旋转把守卫从"头部"挪成"头部一次 + 底部每轮"
> 之后，`break` 路径与底部 `jcc` 的**支配关系变了** —— 某些 `break` 出去的
> 路径会绕过本该执行的归纳变量更新，于是下标算错、越界。

这不是"再加一个特判"能补的：要正确处理，必须先把**完整 CFG**（基本块 +
支配树）建起来，在 CFG 上做旋转，而不是在扁平指令表上就地拼。
那正是 `07-gaps.md` §5 里 `loop_sum 三件套` 第 ② 项登记的工作。

## 为什么回退而不是留着

项目自己的两条铁律（`07-gaps.md` §5 末尾）：

1. 单点核对全对 ≠ 装起来对 —— 必须反汇编对照或单元素 trace。
2. **前置条件不满足就回滚并登记重启条件；错误代码比没有代码更糟。**

这次的证据很干净：形状对、b1 无收益、b9 崩。留着只会让 b9 一直红，
并且把"扁平表上拼控制流"这个错误做法固化进管线。已 `git checkout` 回退，
代码不在树上。

## 已知边界 / 遗留

- **重启条件**：先建 CFG（基本块 + 支配树），再在 CFG 上做旋转。
  在那之前不做任何"扁平指令表上的控制流变换"。
- **b1 即便形状正确也没收益**：说明这条循环的瓶颈不在分支数上
  （`cmovns` 的依赖链 + 每轮 `cmp` 更可能是瓶颈）。这与 v2.60「无帧函数
  无收益」、v2.88「无分支回绕慢 6.6×」是同一类结论：**这条循环对指令级
  小改动不敏感**。下次优化 b1 应从依赖链 / 向量化入手，不要再在指令条数上做文章。
