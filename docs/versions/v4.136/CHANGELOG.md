# v4.136 — 零比较惯用法：`cmp r,0` → `test r,r`（产物更小、依赖更短）

- 日期：2026-11-25
- 任务：发射器层通用微优化。零比较（`if x == 0` / `while n != 0` / `if !ok`）
  在基准与编译器自身里都极常见，`cmp r64,0` 是 4 字节且要读立即数；
  `test r64,r64` 是 3 字节且不读内存/立即数，是 x86 标准零比较惯用法。
- 影响面：编译器（stage-1 发射器 `_cmp_imm`，不动 IR / pass / vloc）

## 等价性（本版全部分量）

对任意 64 位值 `r`：

| 指令 | ZF | SF | PF | CF | OF |
|---|---|---|---|---|---|
| `cmp r,0`（`r-0`） | r==0 | r<0 | r 低字节奇偶 | 0 | 0 |
| `test r,r`（`r&r`） | r==0 | r<0 | r 低字节奇偶 | 0 | 0 |

五者完全相同（AF 未定义但**任何 Jcc/setcc/cmov 都不读 AF**），
所以对每个条件跳转/条件传送都逐位等价，与有符号/无符号语义无关。

## 改动

`_cmp_imm(code, d, v)`（`cmp r64, imm` 的唯一发射点，`OP_CMPI`/`OP_JCMPI`
共用）：`v == 0` 时改发 `_test_rr(code, d, d)`（`REX.W 85 /r`），否则原样 `_alu_imm`。

## 收益

| 项 | 结果 |
|---|---|
| 全量 76 基准 ELF 体积 | **23 项变化，合计 −34 字节**（每处零比较省 1 字节） |
| 本机 min-of-7 计时 | b44 0.9934、b34 1.0002、b78 1.0039、b61 1.0050（**噪声内，无可分辨收益**） |

诚实结论：体积确实变小，但热循环里零比较占比很低，**本机测不出速度收益**；
保留理由是语义等价、产物更小、零风险，属教科书式通用改进。

## 已知边界 / 遗留

- 只改 `_cmp_imm`（寄存器零比较）；`_cmp_imm0` 是既有独立 helper，未动。
- 不触及 `test r, imm`（那与 `and` 等价但不含零比较场景）。
- 本机计时无显著收益；CI 权威基准待推送后实测（预计同为体积收益为主）。

## CI 实测（run 45544891699，推送后权威口径）

三个 job 全绿（含 macOS，这次无抖动），**两平台 76/76 跨语言校验和全部一致、
零 mismatch**。

| 平台 | 几何平均 qlm/C | >1.5× 项数 |
|---|---|---|
| Windows（AMD EPYC） | 1.992 | 42/76 |
| Ubuntu（x86_64） | 1.513 | 32/76 |

如本机结论，零比较惯用法是**体积优化**（每处 −1 字节），热循环占比低，
跨 run 的几何平均差异（1.513 / 1.992）落在 runner 噪声与 CPU 差异范围内，
**不声称任何比值收益**。正确性由 76/76 校验和 + 本机 `qlmc_test` 136/0 +
`bootstrap_test --strict` 不动点共同保证。
