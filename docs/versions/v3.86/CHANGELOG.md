# v3.86 — 发现严重缺陷 §7.47：`while flag && ...` + `if/else` 里循环只跑一轮

- 日期：2026-11-02
- 任务：为 v3.84 失败的优化补"正确性判据"（写标志位循环的差分夹具），
  结果撞出一个**已发布版本里的既有缺陷**。
- 影响面：`tests/selfhost/s47_flagloop.qma`（新增复现件）、
  `docs/07-gaps.md`（新增 §7.47）
- 代码改动：无（纯夹具 + 文档）

## 起因

v3.84 试过把 `while go == 1 && ...` 里的 `go = 0` 改写成 `break`，结果
校验和错了、程序提前退出。当时的结论是"控制流变换不能只靠局部模式匹配"，
并写下了下一步：**先建一个"标志位循环"的差分夹具，再动手**。

这一版就是去做那个夹具 —— 结果夹具一跑，**当前 qlmc 就有 3 行不一致**。

## 缺陷本身

```quelmara
fn main() {
    let s = "   abc"
    let mut p = 0
    let mut go = 1
    while go == 1 && p < 3 {
        let c = s[p]
        if c == 32 {
            p = p + 1
        } else {
            go = 0
        }
    }
    print(p)          // stage-0: 3    qlmc: 1
}
```

**三个要素同时出现才触发**（已二分）：

1. 循环守卫是 `flag == 1 && <另一个条件>`；
2. 循环体内有 `if/else`，其中一支改 `flag`；
3. 循环体内有**字符串下标** `s[p]`。

去掉任一条就正确。

**IR 层的现象**：`go == 1` 那条 `JCMPI` 变成 NOP（`go` 明明在体内被
`CONST go, 0` 改过，不是常量），而且循环尾的 `JMP` 从跳**循环头**变成跳**出口**。

## 一个会误导人的排查信号

逐个 `QLM_SKIP_PASSES` 跳过 8 个 pass，**每一个都能让结果变正确**。

这个信号本身有误导性 —— 它让人以为"是那个 pass 的错"，实际是"任何扰动
都改变了 pass 之间的状态耦合"。所以文档里明确写了：**不要靠"再加一个
pass 修补"，根因是状态耦合**。

## 已确认：错在优化层，不在 lowering

`--no-opt` 下 `JMP` 确实是 `imm=1`（正确的循环头）。所以 lowering 是对的，
优化层把 `JCMPI` 消成了 NOP 并把 `JMP` 目标改错。

## 夹具的处理

`s47_flagloop.qma` 覆盖 6 种形态：基本形态 / 循环后仍读 flag / 循环外
重新赋值 / 两个循环串联 / flag 参与返回值 / 循环内重新置 1。

**故意不登记**进 `tests/qlmc_test.py` 的 CASES 列表 —— 项目没有
"已知失败"豁免机制，登记会让 CI 一直红，失去"有变化才报警"的信号价值。
夹具头部写清了这一点和复现命令，等 §7.47 修好后再加。

## 为什么现有回归没抓到

`s1_basics` / `s3_manyfns` 等夹具里的循环体内都没有"`if/else` + 字符串
下标"这个组合。**这是回归覆盖的真空** —— 而这个组合在真实代码里极常见
（`b9_json` 的 `jws` 就是），只是因为它的校验和碰巧没受影响所以一直没暴露。
