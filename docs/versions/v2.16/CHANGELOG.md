# v2.16 — qlmc 后端完全重写：真 IR + 线性扫描分配 + 按函数多核

- 日期：2026-10-24
- 任务：后端完全重构——用自研语言重写 codegen，多核并行，一次性写完
- 影响面：自举层（`bootstrap/qlmc/qlmc.qma` 后端全部重写）/ 测试 / 文档

## 主事件

v2.15 的 qlmc 是「直接从 AST 发字节 + 全溢出」：每个值都落帧槽，表达式用
RAX/RCX 双累加器，没有 IR、没有寄存器分配、编译是单线程。这一版把**后端整层
推倒重写**，前端（词法 / 递归下降 / 平坦 AST）沿用——它是差分对拍过的，没必要动。

```
AST ──lower──▶ 三地址 IR ──线性扫描──▶ 带位置的 IR ──emit──▶ 机器码
                                                  │
                                          按函数分片，多线程并行
```

### 1. 真 IR（`Ir`：op / dst / a / b / imm）

值用虚拟寄存器编号，标签用 id，26 个操作码。分配与发射彻底解耦：分配只看活跃
区间，发射只看位置，谁也不认识 AST。v2.15 里「右操作数先落帧槽」那种形状是被
RAX/RCX 双累加器逼出来的，现在不存在了。

### 2. 两段式寄存器分配（不再是全溢出）

| 值的类别 | 位置 | 理由 |
|---|---|---|
| 变量（`let` / 形参） | 函数内**固定** RBX / R12-R15（5 个 callee-saved） | 固定分配天然跨循环、跨调用成立，不需要 SSA 与 phi；满了落帧槽 |
| 临时值（表达式中间结果） | **线性扫描**，池是 R8-R11（caller-saved） | 区间短，扫一遍就够 |
| 跨调用的临时值 | 直接落帧槽 | 调用会清 caller-saved；这样就不必在调用点插溢出代码 |

发射序列自己只用 RAX/RCX/RDX 当暂存（除法 / setcc / 实参寄存器），**永不被分配**，
所以不存在「分配器挑了一个发射器要用的寄存器」这类隐蔽冲突。

### 3. 发射到位（让分配真的兑现）

- `_lower_into`：赋值 / `let` 把结果**直接算进目标变量**。`a = a + b` 从
  `mov r8,rbx / add r8,r12 / mov rbx,r8` 三条变成 `add rbx,r12` 一条。
- `_lower_cond`：条件位置直接发 `cmp + jcc`（新操作码 `OP_JCMP`，dst 存 cc），
  不再 `setcc / movzx / test / jz` 四条。
- `print(bool)` 的分支序列提成运行库例程 `__print_bool`，发射器少一条特殊路径。

### 4. 按函数多核（`_compile_range`）

每个工作线程拿到 arena 里自己那段，把分配给它的函数编成字节写进去；主线程
按函数序拼装 + 统一回填。函数之间没有共享可变状态，**所以不需要任何锁**；
拼装顺序固定，**所以线程数不影响产物字节**。

```
arena: [0..63] 线程表（lo/hi/base/cap）  [64..] 函数表（每函数 7 字）
worker: 只写自己那段 → 无竞争；每函数写自己那 7 字 → 无竞争
main:   按 fi 升序拷字节 → 确定性
```

`-j N` 可强制线程数；`-j 1` 走**同一条代码路径**（只是不 spawn），所以
`-j1` 与 `-jN` 的 exe 逐字节相同——这条由测试钉住，不是口头承诺。

### 5. 顺手修掉的三个真实缺陷（都是重写时暴露的）

| 缺陷 | 现象 | 根因 |
|---|---|---|
| 区域基准错位 | 编译任何程序都「vec index out of bounds」 | 工作线程写的是**区域相对偏移**，主线程按 arena 绝对偏移回读 |
| 常量重名 | `iat.set(I_EXIT, …)` 写到下标 21 | 新 IR 操作码用了 `I_EXIT`，与 p1 的 IAT 槽常量同名；改 `OP_*` |
| 函数基址从 0 起算 | 产物能出但一跑就崩 | 拼装时 `off` 应为「入口 + 运行库」之后的长度，写成了 0 |

`loop_sum` 只涨 17% 是**预期**的：热点是 `idiv`（~26 周期），寄存器分配省下的是
访存，不是除法。要再快得换「除以常数 → 乘逆元」，那是常量折叠/强度削减的活，
不在本版。

**并行为什么只有 1.5×**：后端阶段里线程创建 ~200 µs/个是固定成本，800 函数时
约占 0.6 ms；更主要的限制是**前端单线程**——`s3_manyfns` 的 16 ms 里有 13 ms 是
词法+语法。并行只覆盖了后 20% 的流水线，这是下一版的位置（见 07-gaps §3）。

## 已知边界 / 遗留

- **子集仍是 S2**：后端换了，语法面没扩。struct/enum/match、数组、vec/map、f64、
  泛型、闭包、切片、`defer`、`for`、`break`/`continue`、`import` 都不支持——
  差分夹具之外的东西照样编不过（fail-fast，不静默）。
- **并行只覆盖函数体**：词法 / 语法仍是单线程，是当前墙钟的主要部分。
- **分配器是「变量固定 + 临时扫描」两段式**，不是全局线性扫描：变量超过 5 个就
  落帧槽（`tests/selfhost/s3_manyfns.qma` 的函数只用 2 个变量，够用）。要做
  「变量也参与扫描 + 溢出重写」需要活跃区间分裂，留给后面。
- **没有常量折叠 / 强度削减 / CSE**：`loop_sum` 的 `% 13` 仍是 `idiv`。
- **arena 固定 16 MB**：单个函数超过约 16 MB/线程 会 fail-fast 报「编译缓冲不够」，
  不会静默截断。
- `assert` 的 stderr 文本仍只有消息本身（差分只比 stdout 与退出码）。
