## 为什么"同名"这件事必须先改解析期

v1.44 的限定语法是**纯语法糖**：解析时把 `lib.fn()` 的模块段剥掉，改写成
`("call", ["fn"])`，只在一个集合里记一笔 `(模块, 名字)` 供链接期校验。这在
"扁平唯一"的前提下没问题——`fn` 只有一个，剥不剥都一样。

一旦放开同名，这个做法就**结构性失效**：

```quelmara
fn helper() -> str { return "本文件" }
...
helper()        // 解析后：("call", ["helper"])
util.helper()   // 解析后：("call", ["helper"])  ← 同一个节点形状
```

两个节点一模一样，链接期无从分辨谁该指向谁。所以第一件事是把模块信息
**留在 AST 里**：解析期把限定引用编成 `模块串 \x01 名字`（`QSEP` 分隔符，
标识符里不可能出现），链接期再按节点解析。这也顺带把"指向 + pub"校验从
"集合近似"换成了"逐节点精确"。

## 设计：只在真的重名时才动名字

| 情形 | 结果 |
|---|---|
| 名字只在一个文件里声明 | **一个字节都不改**（既有程序走同一条路径） |
| 主文件与 import 重名 | 主文件保留原名；导入方变 `<模块>__<名字>` |
| 两个 import 之间重名 | 两边都加前缀；未限定引用 = 歧义报错（提示 `lib.name`） |
| 同名 struct / enum | 方法、派生函数跟着换前缀（`T__m` → `<模块>__T__m`） |
| 同名非 pub 私有函数 | 各归各的模块（前缀保证不撞） |

前缀取 import 串：`import std.json` → `std__json`——与源码里的写法同源，
报错和反汇编里都认得出是哪个模块。

**为什么主文件不动**：入口那一侧是用户手写的调用点，让它保持原名意味着
"引入一个同名库"不会连带改动本文件的任何一行。反过来，库侧改名是用户
看不见的（他本来就要写 `lib.name` 才能引用）。

未限定引用的解析顺序是 **本文件声明 > 唯一外部声明 > 歧义报错**。第三条是
刻意的：同名时"猜一个"比报错危险得多。

## 设计：模块版本

```quelmara
module util "1.2.3"     // 声明
import util ">=1.2"     // 要求（同 major 且 >=）
```

- 检查口径：**同 major 且实际 >= 要求**；不满足、或模块没声明版本，都编译期
  报错（报错带实际版本 + 文件名）。
- 版本号写法 `"1"` / `"1.2"` / `"1.2.3"`，可带 `>=` / `^` / `=` 前缀（三者同义）。
- **不做 semver 求解**：版本只用来挡住"明显不兼容"的导入；依赖选择、锁、
  传递依赖冲突合并是 qpm 的活（v1.99 已做，见 `05-toolchain.md`）。

## 实现要点

1. **限定引用的编码**（`qref()` / `QSEP`）：解析期把 `lib.name` 编成
   `lib\x01name`，出现在 `call` / `enumlit_pos` / `path` / `pat` 四种节点里。
2. **`link_modules()`**：在 `load_program` 里、合并之前跑。建各文件的声明表 →
   算重名集合 → 生成改名表（主文件除外）→ 一趟 AST 重写（声明名 / 类型位 /
   引用位 / 限定引用）→ 返回新 `files`。
3. **重写是作用域感知的**：`let` / `for` / 参数 / `match` 绑定会遮蔽同名全局，
   被遮蔽的引用不重写（否则会把局部变量名改掉）。
4. **方法名跟着类型走**：Lower 的派发按 `Type__method` 拼名字，所以类型改名时
   同前缀的函数（含 `@derive` 生成的 `T__json`）一并换前缀，两边必须一致。
5. **`@derive` 的生成物插回声明处**：v1.96 把展开挪到了文件末尾（为了前向声明
   的类型），但那会改变 `parsediff` 的声明顺序口径——现在展开仍在末尾，生成物
   按登记时的下标插回原位，两边的 dump 逐行一致。

## 已知边界 / 遗留

- **`const` 不参与 mangling**：它在解析期内联，跨模块同名不同值仍然报错
  （同值则幂等）。要让 const 也按模块区分，得把内联改成"按模块取值"，成本
  远大于收益。
- **同名 `interface` 视为同一份契约**：签名一致即幂等，不一致报错（v1.88 起的
  规则）。接口是"结构化契约"，同名即同约是刻意的。
- **限定 struct 字面量仍不做**（`lib.Point { x: 1 }`）：字段表在被导入模块里，
  解析期无法校验。用 pub 工厂函数，或先 `let p = lib.make(...)`。
- **类型位不支持限定**（`let p: lib.Point`）：类型名走扁平解析，同名类型靠
  mangling 区分，调用方拿到的是函数返回值，不需要写类型名。
- **模块版本不做 semver 求解**：`">=1.2"` 只表达"至少 1.2、同 major"；区间、
  预发布、锁文件都是 qpm 的职责。
- **重名检测是全程序口径**：只在被 import 的文件之间比，没被 import 的文件不参与。
