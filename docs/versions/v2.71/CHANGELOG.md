# v2.71 — int→str 不再把数字拷一遍

- 日期：2026-10-27
- 任务：压 b5_string 的 itoa 开销
- 影响面：`tools/stage0/qlm_native.py`（`__str_from_i64`）

## 根因：为了给 8 字节长度前缀腾位置，数字被整体拷一遍

旧布局：数字从缓冲区尾部往左写到 `[pos+1, 39]`，然后**再拷到
`[8+neg, ...]`**（因为长度前缀固定在字 0、字符串必须从字节 8 开始）。

那个拷贝循环每个数字 ~19 条机器指令（下标运算 + `load8` + `store8` +
越界检查 + 循环控制），6 位数就是 110+ 条 —— 占 b5 一次迭代的 1/6。

## 改法

**字符串不需要落在固定偏移上** —— `__str_len` 读的是 `[ptr-8]`，别处只用
ptr/len。所以：

1. 数字继续从尾部往左写（这次写到字节 47）；
2. 负号写在第一个数字前一个字节；
3. **长度前缀写到数字正前方**（`[pos-7, pos]`，高 7 字节清零、低字节是
   长度，`len < 256`）；
4. NUL 落在固定字节 48；
5. 返回 `buf + pos + 1` —— 前缀正好是它前面那 8 字节。

缓冲区 41 → 56 字节。

## 两个踩过的坑

- **NUL 不能写成 `pos+1`**：`pos+1` 是第一个数字的位置，会把首字符清掉
  （`str.to_int() invalid decimal input`）。`pos+1+len` 恒等于 48，所以直接
  写常量 48。
- **返回 `buf + pfx` 会早 8 字节**：`pfx` 递减后指向前缀的**首**字节，而
  返回的必须是**字符串起点**。早 8 字节会让 `__str_len` 读到前缀之前的垃圾。

## 效果

b5_string 本机 min of 5，两轮交替 A/B：38.5 / 35.2 → **34.3 / 31.9**
（−9 ~ −11%）。
