# v2.87 — 归纳削减加**运行期守卫**：上界是形参的循环也能优化（b8 −13%）

- 日期：2026-10-27
- 任务：性能 —— 把归纳削减从"只认常量上界"放宽到"上界是形参"
- 影响面：`bootstrap/qlmc/qlmc.qma`（`_opt_mod_ind` 的守卫分支 + `_mod_ind_apply` 拆分）

## 为什么要放宽

v2.81 的归纳削减要求"`i < N` 且 `N` 是**常量**"，因为 `t = i*C` 溢出会让 `t`
变负，非负前提就没了。但**上界是形参是最常见的形状**：

```quelmara
fn work(n: int) -> int {          // b8_threads1 就是它
    let mut i = 0
    while i < n { acc = acc + (i*7) % 13  i = i + 1 }
}
```

`n` 是形参 → 上界不可证 → 一直吃不到这个优化。CI 上 b8_threads1 对 C **4.29×**、
对 Go **1.44×**，是剩下最大的一项。

## 改法：运行期守卫，不做循环版本化

循环版本化要复制整个循环体（vreg 重映射 + 标签重编号），风险大。这里用更省的
办法 —— **在循环里加一条守卫**：

```
      cmp  i, LIMIT          ; LIMIT = 2^62 / C，保证 i*C 不溢出
      jl   Lfast             ; 常态：走快路
      <原来的魔数除法>        ; 只有 i 极大时才走
      jmp  Ldone
Lfast: r = v                  ; 快路：取增量余数
Ldone: ...
```

**为什么这样是安全的**：`i` 在循环内只有一个定义 `i = i + s`（`s > 0`），单调
递增 —— 一旦越过 LIMIT 就再也回不到快路，所以 `v` 被慢路弄脏也无所谓。
非负前提仍然由"`i` 初值是常量 `k >= 0` + 步长为正"保证（这条没放宽）。

`LIMIT` 存进一个变量（`2^62/7 ≈ 6.6e17` 放不进 `imm32`，用不了 `JCMPI`）。

## 效果

| | 改前 | 改后 |
|---|---|---|
| b8_threads1（本机 min of 3，交替） | 333 / 347 / 377 ms | **296 / 305 / 299 ms** |
| b1_int（常量上界，走的是无守卫路径） | 20.2 / 21.6 ms | 20.5 ms（不变） |
| 校验和 | 959999992 / 119999988 | **完全一致** |

**只有 13%，不是预期的 2×。** 原因：热循环现在只剩 9~10 条指令，已经不是
吞吐瓶颈，而是被**两条 taken branch**（回绕的 `jl` + 循环回边）卡住。
试过无分支回绕（`t = v-D; m = t>>63; m &= D; v = t+m`），但编译器在
`_vnew` 新建临时值后崩了（`vec index out of bounds`），本轮没时间查，已回退。
**这是下一轮的第一顺位**——回绕无分支化 + 循环展开 2×，理论上还能再快 1.5×。

## 三个坑

1. **重扫把同一个循环反复变换**。守卫版把原 DIVC 留在原地（只有快路被换成
   `MOV`），而我变换完 `i = 0` 重扫 —— 于是同一个窗口被一遍遍变换，直到把
   帧槽吃光（`work` 报"需要 417 个槽"）。修法：用**循环头标签 id** 记一个
   `done` 集合（下标会因插入漂移，标签 id 不会）。
2. **重构时把 `hit+1` 写成了错的**。常量上界那条路径原来是
   `ir.set(hit + 1, MOV)`（因为循环头的 CONST 先插、整体 +1）；我把 CONST 的
   插入挪到最后之后，`hit+1` 就变成了 DIVC **后面**那条指令 —— 把
   `add acc, r` 覆盖掉了。**b1 的校验和从 119999988 变成 0**，静默错。
   抓到它的是"每改一次就核校验和"这个习惯，不是测试。
3. **帧槽又爆了**（`_opt_mod_ind` 要 417 > 416）→ 把变换部分拆成
   `_mod_ind_apply`。这是这个文件第四次因为 416 拆函数。
