## 症状

```quelmara
struct P { x: int }
let p1 = P { x: 1 }
let p2 = P { x: 1 }
print(p1 == p2)      # false（应为 true）
```

不崩、不报错，只是答案错。根因：聚合值在寄存器里存的是**帧槽地址**，
而 `==` 落到整数比较（`OP_CMP` / `OP_JCMP`），比的是两个地址。

顺带发现 **stage-0 也有同一个缺陷**（实测 `p1 == p2` 输出 `false`，
`p == p` 输出 `true` —— 后者只是因为同一个变量落在同一个槽）。所以这条
**不能用差分验证**。

## 修法

`_emit_bin` 里在比较分支之前插入聚合分支：

1. 两侧取**区域基址**（`OP_ADDRV` 取帧槽地址）；
2. 按 `_ty_size(fc, tl)` 调运行库 `mem_cmp`（`RT_MEMCMP`，返回首个不同
   字节的差值）；
3. 判"差值为 0"：`OP_CMP eqv, d, z, _cmp_cc(P_EQ) + 0x10`（`sete`）。

**`_lower_cond` 也要改**：`if p1 == p2 { ... }` 走的是那条路径，它原来
对非 str 一律 `OP_JCMP`（比地址）。改成聚合也走 `_emit_bin`，再按结果跳。

只处理 `==` / `!=`：聚合的 `<` / `>` 没有自然定义（stage-0 也是地址比较），
保持原状。

### 一个踩到的坑

第一次写 `setcc` 的判据时写了 `0x04`，那是错的 —— `_cmp_cc(P_EQ)` 返回的
是 **jcc** 形态 `0x84`（`je`），`setcc` 是 jcc + 0x10 = `0x94`（`sete`）。
写成 `0x04` 会编成别的 ALU 操作。

## 为什么这个夹具不是差分用例

其它 `sNN_*.qma` 都是"stage-0 与 qlmc 各编一次、输出逐字节比较"。这一个
**不能**这样做 —— 拿一个已知错误的实现当基准，只会把缺陷"固化"成契约。

改成**正向断言**：用 `assert` 钉住语言定义（`02-language.md`：聚合的 `==`
按字段/变体逐项比较），跑通即通过。

配套加 `case_qlmc_aggeq()`（`tests/run_win_tests.py`）：只验 qlmc 侧。
