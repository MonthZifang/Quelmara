# v2.52 — 常数除法省掉符号重算（`%` 18 → 15 条指令）

- 日期：2026-10-25
- 任务：严重优化性能与加速比（`b1_int` / `b8` 的 3.7 倍）
- 影响面：自举层（`_emit_divc` 两条路径）+ 新增符号回归夹具

## 为什么会有"重算"

v2.48 的常数除法序列里，`mul rdx` 会同时毁掉 `RAX` 和 `RDX`，而符号位原本存在
`RAX` 里 —— 所以算完 `qa` 之后又**重算了一遍** `sign`：

```
mov rdx, rcx
sar rdx, 63          ← 第二次算符号位（第一次的已经没了）
```

两条指令的浪费，但当时没有第四个寄存器可用：`RAX`/`RCX`/`RDX` 是发射器保留的
（永不持有 vreg），`R8-R11` 是临时值池。

## 现在可以借 `R11`

`R11` 是 caller-saved 的临时寄存器。只要**在这一点没被占**，就能借它存 `sign`：

```
mov  rcx, x
mov  r11, rcx
sar  r11, 63         ← sign 存 R11，一路保留
mov  rax, rcx
xor  rax, r11
sub  rax, r11        ; |x|
movabs rdx, m
mul  rdx
mov  rax, rdx
shr  rax, s
xor  rax, r11        ← 直接用，不重算
sub  rax, r11        ; q
```

`_reg_busy_at(fc, R11, i)` 扫一遍 vreg：只要没有 `vstart <= i <= vend` 且
`vloc == R11+1` 的值，就走快路径；否则退回重算版（**两条路径都必须保留**）。

**为什么这个检查对变量恒为 0**：变量永远落在 cs 寄存器（`RBX`/`R12-R15`/`RSI`/`RDI`）
上，不可能在 `R11` 里。所以只有临时值能挡住它。

结果：`%` **18 → 15** 条、`/` **15 → 12** 条。

## 又踩了一次 REX（坑表 #49 的同一个坑）

第一版把 `mov r11, rcx` 写成 `4D 89 CB`。**REX 应该是 `0x49`（W|B），不是 `0x4D`
（W|R|B）** —— 多置了 R 位：

- `mov r11, rcx` 变成 `mov r11, r9`（源寄存器被扩展成 r9）；
- `sar r11, 63` 的 `ext` 字段从 7 变成 15 → 非法组。

表现：**负数除法的 `|x|` 算成 `0xFFFF…FFFF`**，于是走了无符号除法 ——
`-1 / 3` 得到 `6148914691236517205`。

**是"负数差分测试"抓到的**。之前所有夹具里的除法都是正数，`s21_f64`、`s8_map` 之类
也碰不到这个形状 —— 一个只测正数的差分测试对符号分离的实现**毫无覆盖力**。

## 新增夹具 `s25_divmod.qma`

13 个 x（`0`/`±1`/`±12`/`±13`/`±1000000`/`±INT64_MAX`/`±2^31`）× 6 个除数
（`2`/`3`/`7`/`13`/`1000`/`2147483647`）× `/` 与 `%` = **156 组**，与 stage-0 逐字节对拍。

## 剩下的（§7.31）

- **`b9_json` 3.8×**：主要差距是**函数调用开销**（`jws`/`jstr`/`jval` 每 token 调一次，
  prologue + epilogue 约 15 条指令），C 会内联。qlmc 没有内联器 —— 那是下一个量级的工程。
  其次是每字节一次越界检查（要范围分析）。
- **`b2_float` 3.0×**：f64 仍住帧槽，要上 XMM 寄存器文件。
- **`b4_array` 3.4×**：内存带宽。
