## 结果先说：没做成，但把两条死胡同试完了

| 尝试 | 结果 |
|---|---|
| `wsprintfA`（user32，qlmc 已经在用）+ `%.6f` / `%e` | **写不出东西** —— user32 那个精简版 `wsprintf` **不支持浮点**，只认 `%d/%u/%x/%s/%c` |
| msvcrt 的 `sprintf`（导入表已正确写出 `strtod` + `sprintf`，IAT 槽也核对过） | **仍然写不出东西** —— 无 CRT 上下文里 msvcrt 的格式化子系统没初始化 |

**管道本身是通的**：把 `__f64_fmt` 换成一个"往缓冲写 `OK`、返回 2"的桩，`print` 正确打印出 `OK`。
所以问题确实在格式化函数，不在 `print(f64)` 的接线上 —— 这一条排除了"接线错"的可能，
省掉了后面瞎猜。

这也解释了 stage-0 为什么宁可手写 `__f64_to_str`（两百多行）也不用 `wsprintf`：
它根本印不了浮点。

## 排错过程中修掉的三个真 bug（虽然最终功能没落地）

1. **影子空间冲突**：把 `buf`/源槽存在 `[rsp+0x20]`/`[rsp+0x28]` —— 那正是 Win64 的
   32 字节**影子空间**，被调方会写它。结果 `sprintf` 返回后读到的是垃圾。
   挪到 `[rsp+0x30]`/`[rsp+0x38]` 才对。（现象：打印出来只有格式串的末字符 `f`/`e`）
2. **载入的是槽地址而不是槽里的值**：`movsd xmm0, [rsp+0x38]` 读的是"槽的地址"的位模式，
   应该先 `mov rdx, [rsp+0x38]` 再 `movsd xmm0, [rdx]`。
3. **rdata 字符串哨兵不可靠**：想给 `"%.6f"`/`"%e"` 加 `FK_STR` 的 -5/-6 哨兵，
   `nl[2]` 打出来是 830（正确）但解析出来的地址偏 24 字节。绕开了 —— 改成
   **在栈上直接构造格式串**（`"%.6f"` 与 `"%.6e"` 只差一个字节，科学计数分支改一个字节即可），
   不再依赖 rdata 哨兵。这条经验对以后加运行库字符串有用。

## 下一步的配方（已写进 07-gaps §7.26，可照着做）

只能像 stage-0 那样手写整数路径。口径（逐行可对照 `__f64_to_str`）：

- `|x| == 0` → `0`；NaN → `nan`；±inf → `inf` / `-inf`
- `1e-6 <= |x| < 1e12` → 定点：`u = (i64)(x*1e6 + 0.5)`、`ip = u/1e6`、`fp = u%1e6`；
  打印 ip，`fp != 0` 时打 `.` + **6 位零填充**的 fp，然后**去尾零**（连 `.` 一起去）
- 其余 → 科学计数：把 x 归一到 `[1,10)` 并数指数；`m = (i64)(x*1e6 + 0.5)`（进位到 1e7 时
  `m = 1e6`、指数 +1）；打印 `m/1e6`，余数非零时打 `.` + 6 位 + 去尾零；再打 `e` + 符号 + 指数

**可复用的现成件**：`__i64_fmt(buf, v) -> len`（整数 → 十进制，无填充）。
**需要新写的**：6 位零填充（从尾部往前写 6 个 `'0' + v%10`）、归一到 `[1,10)` 的循环。

去尾零的代码在这一版里已经写通并验证过（找 `e`、只在尾数里删 0、把指数部分整体前移），
回退时一起删了 —— 下次照 07-gaps §7.26 重写即可。
