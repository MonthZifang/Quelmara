## 7.14：传错类型编译通过，运行期静默错值

v2.07 写 `std/net/addr` 时把 `str_find_from(s, from, needle)` 的实参写反，
编译器一句都不说，程序当场 SIGSEGV。

```quelmara
fn g(a: str, b: int, c: str) -> int { return b }
fn main() { print(g("abc", "not-int", "x").to_str()) }   // 编译通过
```

```
r=140699978051634      ← 把 str 数据指针当 int 原样返回
```

根因：调用点只做**个数**校验（"需要 N 个实参"），加上数组长度 / 接口 /
闭包的专项校验，`str` 与 `int` 之间什么都不查 —— 它们在 IR 里都是一个
8 字节槽。**这属于"静默错值"，比编不过难查得多。**

## 修法：保守推断，宁可漏报不误报

关键是**不能误伤**。stage-0 的类型传播本身有缺口（§7.28：容器/返回值
会丢元素类型），在这种基础上做严格检查会把正确程序拦下来。

所以只判"能确定"的：

| 表达式 | 判得出吗 |
|---|---|
| 字符串字面量 `"x"` | ✅ str |
| 整数字面量 `42` | ✅ int |
| 布尔字面量 `true` | ✅ bool |
| 用户函数调用 `f()` | ✅ 查 `fns_ast[name]["ret"]` |
| 内建调用 `len(s)` | ✅ 查 `_BUILTIN_SCALAR_RET` 小表 |
| 变量 / 字段 / 下标 / 二元运算 / 泛型 | ❌ 放行 |

`int` ↔ `bool` 互传**不拦**（语言允许 0/1 当 bool 用，历史上也这么写）。

报错形态：

```
函数 g 的第 2 个形参期望 int，实参是 str
（v3.31 起调用点做标量类型比对；这以前会静默按位重解释）
```

`_BUILTIN_SCALAR_RET` 只登记"返回 str/int/bool 无疑"的内建。
**不确定的一律不登记** —— 漏登记只是少一次检查（放行），
错登记会让正确程序编不过。

文件编不过。
