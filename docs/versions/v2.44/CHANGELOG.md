# v2.44 — 优化层（Quelmara 自己写的 IR pass）+ 帧按需分配，修掉两个栈溢出

- 日期：2026-10-25
- 任务：检查 qlmc 的优化层 → 用 Quelmara 写一个真的优化层，并全面优化性能
- 影响面：自举层（新增 `_opt` 家族 / `_frame_bytes` / `_mov_imm` 重写）/ 测试 / 文档

## 先说体检结论

v2.43 的 qlmc **没有优化层**：唯一的"优化"是 `_lower_into` 把赋值直接算进目标变量
（`a = b + c` 只发一条 `add`），`_fold` 只服务 `const` 声明。三地址 IR 上面没有
任何 pass，源码注释里也写着"没有 CSE/调度/内联，IR 只是多一层搬运"。

拿 qlmc 编自己（492 544 字节）做基线量了一遍，浪费长这样：

| 现象 | 条数 | 说明 |
|---|---|---|
| `movabs reg, imm64` | 9 317 | 其中 **3 159 个是 0**、**6 117 个在 imm32 内**、只有 41 个真需要 64 位 —— 99.6% 白付 4~7 字节 |
| `mov rax, X` + `mov [rbp+d], rax` | 3 277 | 源已经在寄存器里，可以直接 `mov [rbp+d], X` |
| `mov X, rax` + `mov rax, X` | 2 073 | 互相抵消的两条（CALLRT 结果 → 打印/返回） |
| `jmp` 跳到紧接着的下一条 | 942 | 函数尾的隐式 return |
| 每个函数固定 4 KB 帧 | 全部 | 见下，这个不是浪费，是**bug** |

## 最重的那个：4 KB 固定帧 → 两个栈溢出

`FRAME = 4096`，**每个函数**都 `sub rsp, 4096`（奇数个 callee-saved 时 4104）。
PE 的 `SizeOfStackReserve` 只有 1 MB，所以递归深度上限约 250 层。实测：

- **编译期**：`print(1+1+…+1)` 到 **37 项**就 `0xC00000FD`（STATUS_STACK_OVERFLOW）。
  降级是递归的，一层 AST 要好几帧，36 项能编、37 项就崩。
- **运行期**：`fn down(n){ if n<=0 {return 0}; return 1+down(n-1) }` 在 `n=400`
  时栈溢出（stage-0 的产物跑 1000 没事）。

修法：`_frame_bytes(fc)` 按实际用量算 —— 变量/聚合区看 `C_ST`，临时槽看 `vloc`
里最深的那个，再对齐 16。帧从 **4096 → 16~232 字节**（qlmc 自己那 276 个函数，
没有一个超过 4 KB）。

**踩到的坑（进坑表 #46）**：帧一缩小，`s12_ffi` 立刻挂 ——
`print(metric(0)+metric(1))` 打出 `1921`。原因是 **Win64 的 32 字节影子空间**：
调用点没有 `sub rsp,0x20`（只有 >4 个实参才发 `OP_STKALLOC`），被调方默认
`[rsp .. rsp+0x20)` 可写。以前帧是 4 KB，这块被"顺带"兜住了；帧缩到 16 字节之后
影子空间直接压在活跃槽上，把前一个结果冲掉。所以 `_frame_bytes` 现在固定 +32。

顺带把**临时槽池**改成紧接变量区（`tbase = C_ST`）：以前临时槽从固定的
`SLOT_TEMP(384)` 起，"3 个局部变量 + 1 个溢出临时值"这种函数也要 385 个槽。

## 优化层：`_opt`（全部用 Quelmara 写）

位置：降级之后、分配之前。三条 pass：

| pass | 做什么 |
|---|---|
| 常量折叠 | `OP_CONST` 定义的临时值参与算术/位运算就当场算掉；`MOV 变量, 常量临时值` → `CONST 变量, v` |
| 死临时值删除 | 临时值的定义如果一次都没被读、且操作码是纯的，换成 `OP_NOP` |
| 空跳删除 | `jmp L` 而 L 就在下一条（中间只隔 `OP_LAB`） |

**三条铁律**（已写进 `docs/05-toolchain.md` §1.11）：

1. **只改"指令还在不在"，绝不改下标**。消掉的写 `OP_NOP`，发射时一条字节都不发。
   这样 `vstart`/`vend`、标签位置、`cp` 全部保持有效，不用重建索引。
2. **只动临时值，不动变量**。变量可以被重新赋值，删它的定义会改变别的路径看到的值。
3. **DCE 倒着扫一趟就够**。删一条指令时把它操作数的使用计数减掉，而那些操作数定义
   在更前面 —— 倒序还没走到它们，所以同一条链上的死定义会在同一趟里连着删掉。

### 这轮踩的两个坑

**(a) "临时值单赋值"是错的（进坑表 #47）**。第一版照 SSA 的思路传播常量，
`s15_bitops` 和 `s23_map_grow` 立刻挂：`m.get(k)` 全变 0。原因是 `_map_get` 里
**同一个 vreg 有两个定义** —— 先 `CONST d, 0`（未命中时的默认值），命中后再
`LOAD d, va`。于是 `return m.get(k)` 被"折"成 `return 0`。
修法：先统计每个 vreg 的定义次数（`_opt_ndef`），只有**单定义**的临时值才能当
常量源。

**(b) 优化层的缓冲必须复用**。第一版在 `_opt` 里 `vec.new`，`s3_manyfns`
（200 个小函数）光分配就让编译慢 7%。把 `cok`/`cval`/`use`/`ndef`/`out`
提到 `_compile_range`（每线程一份）跨函数 `clear()` 重用之后，代价降到 3%。

## 发射层：按值选最短编码

`_mov_imm` 从恒定 `movabs imm64`（10 字节）改成三档：
`[0,2^32)` → `mov r32,imm32`（5/6 字节）、`[-2^31,0)` → `REX.W C7 /0 imm32`
（7 字节）、其余 → `movabs`。另外 `OP_CONST` 落帧槽时直接
`mov qword [rbp+d], imm32`（8 字节，原来是 10+8），`OP_MOV` 落帧槽时源已在寄存器
就直接存。

**这里也踩了一个**：第二档写成 `if v >= -2147483648` 漏了下界，于是
`1 << 61` 这种大于 2^32 的正数被当 imm32 截断成 0（`s15_bitops` 打出 `-128`
而不是 `2^61-128`）。正确写法是 `v < 0 && v >= -2147483648`。

## 效果（git worktree 基线双向对照，28 个夹具）

| 指标 | v2.43 基线 | v2.44 | 变化 |
|---|---|---|---|
| `.text` 真实字节（28 夹具合计） | 203 325 | 181 085 | **−10.9%** |
| 指令数（同上） | 40 435 | 38 372 | **−5.1%** |
| `movabs` 条数（qlmc 编自己） | 9 317 | 17 | **−99.8%** |
| 函数帧（qlmc 编自己，276 个函数） | 4096 / 4104 | 16~232 | **−94% 以上** |
| stage-2 体积（源码涨了 2.7%） | 492 544 | 459 776 | **−6.7%** |
| 编译耗时 | — | — | **+1.7% ~ +3.2%** |
| 运行期（loop_sum / fib(27) / 递归） | — | — | 中性（−0.1% / +0.5% / +0.3%，均在噪声内） |

逐用例没有一个是负优化。收益最大的几个：`s3_manyfns` −19.2%、`s15_bitops` −19.2%、
`s23_map_grow` −13.7%、`s8_map` −12.6%、`s20_mem` −10.8%。
收益最小的是 `fib` −2.4%、`loop_sum` −2.8%（最小的程序，本来就没多少可折）。

**编译耗时的代价换来的是产物 −10.9%**，而且 `-jN` 照样逐字节相同。

## 还没做（有意留的）

- **强度削减 / CSE / LICM**：要循环信息与支配关系，是另一个量级的工程。
- **拷贝传播 / 临时值合并**：v2.43 的 `_map_set` 段错误就是"合并两个定义"引起的，
  变量不是 SSA，不碰。
- **临时槽池上限 128**：深嵌套表达式到 66 项就 fail-fast。要放开得先给 qlmc
  自己做栈探测（帧 > 4 KB 的红线，§7.17），是独立的一步。
- **f64 不进 XMM 寄存器**：全走帧槽，是性能上最大的一块，但属于"另一个量级的改动"。
