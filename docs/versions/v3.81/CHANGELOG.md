## 复核方法

按 §7.4 的原记录重建复现件（FIPS-197 C.1 向量）：

```
key = 000102...0f
pt  = 00112233445566778899aabbccddeeff
期望  69c4e0d86a7b0430d8cdb78070b4c55a
原实测 69c4e0d86a7b0430d8cdb78070b4c500   ← 最后一个字节丢了
```

三种编译方式结果**全部正确**：

| 编译方式 | 结果 |
|---|---|
| stage-0（默认优化） | ✅ 标准答案 |
| stage-0 `--no-opt` | ✅ 标准答案 |
| qlmc | ✅ 标准答案 |

**加强验证一：直接调用 vs 包一层包装。** 原记录说"包一层就正确"，现在两条
路都对。

**加强验证二：pass 级扫描。** 把优化器的 **19 个 pass 逐个
`QLM_SKIP_PASSES` 跳过**，每次重编 + 重跑：

```
baseline: 69c4e0d86a7b0430d8cdb78070b4c55a
  baseline OK
sweep done          ← 19 个 pass 全部跳过，没有一次 MISMATCH
```

**没有任何单个 pass 是缺陷来源** —— 排除了"某个 pass 引入坏变换"这个假设。

**加强验证三：高寄存器压力。** 8 个活跃变量与 AES 调用同时存活，结果仍正确。

§7.5 同轮验证：`tests/t73_ghash.qma` 通过、`tests/t48_aes.qma` 通过
（含 GCM 路径，`_gmul_ni` 就是当初出问题的地方）。

## 结论：记"已不可复现"，不记"已修"

v1.31 之后有 v2.59（LICM 默认开启，挖出两个潜伏 bug）、v3.31（64 位立即数
`and`）等多轮优化器修复，但**没有任何一版的记录明确说"修了 §7.4"**。

所以只能说**当前版本不复现**，不能说"定位并修掉了根因"。这个区别很重要 ——
前者是"现状观察"，后者是"因果确认"。

## 把复现件入库

原复现件 `build/_aes_sw.qma` 一直没入库（因为它是"必失败"件）。既然现在
不复现，把它固化成**正向**差分夹具 `tests/selfhost/s45_aesmain.qma`：

| 形态 | 覆盖的理由 |
|---|---|
| 直接调用 | 原缺陷形态 |

三种形态都必须输出 `69c4e0d86a7b0430d8cdb78070b4c55a`。
