# v2.96 — `__vec_grow` 禁止内联：b4 −20%、b9 −3.7%（收掉 v2.93 的 +23% 代价）

- 日期：2026-10-28
- 任务：性能 —— 收口 v2.93 登记的 "b4_array +23% 代价"
- 结论：代价的元凶不是"阈值 60 太宽"这个笼统说法，而是**一个具体的函数**：
  `__vec_grow`（18 条 IR、含 realloc+拷贝循环的冷路径 helper）被内联进了
  push 热循环。给它加 `no_inline`，b4 从 83.9 → 67.3 ms（**−20%**），
  b9 再 **−3.7%**，其余基准全在噪声内。

## 三轮测量，每一轮都在修正上一轮的错误结论

这版的重点其实不是那 20%，是**测量方法本身翻过的车**：

### 第一轮（v2.93 当时）："ban grow 恢复 b4" —— 错

用 `QLM_NO_DCE`/阈值扫参时看到"th=38 崩、th=34 好"之类的悬崖，直觉归因给
"内联变多导致寄存器压力"。**没有做同轮 A/B，结论不成立。**

### 第二轮：带 `no_inline` 打点的两臂 A/B —— 方向反了

写了个 A/B 工具，两臂是"保持源码默认"与"什么都不做"——但源码里已经加了
`f.no_inline = True`，**"什么都不做"的那臂根本没撤销它**；两臂实际都在
ban 状态下跑，测出 delta≈0，差点把整个方向判死。

教训：**A/B 的每个臂必须独立验证生效**。第二版工具加了臂生效探针
（检查 `main.inlined_from` 里到底有没有 `__vec_grow`），才拿到真数据。

### 第三轮：三臂全组合 —— 机制钉死

| 臂 | b4 | b5 | b9 |
|---|---|---|---|
| grow 不内联 + memcpy 内联（本版方案） | **67.3** | 110.0 | **76.1** |
| grow 不内联 + memcpy 不内联 | 67.7 | 110.7 | 76.0 |
| grow 内联 + memcpy 不内联 | 83.7 | 110.3 | 76.1 |
| grow 内联 + memcpy 内联（= v2.93 原状） | 83.9 | 110.1 | 78.9 |

读法：b4 的 20% **全部**跟着 `grow` 这一列走，`memcpy` 列基本无关；
b9 的 3.7% 只在 "grow 内联 + memcpy 内联" 时出现。所以只 ban grow、
不动 memcpy —— 最小干预，实测收益拿满。

### 传导路径：为什么一个冷分支值 20%

`__vec_grow` 的 IR 有 18 条（判满 → `__realloc` → `__memcpy` 搬旧数据）。
它挂在 push 的内联展开里：`v.push(x)` → `__vec_push`（已内联，12 条）→
`ln==cp` 分支 `call __vec_grow`。阈值 28 时 grow 进不了内联；阈值 60 时
**它也进了每个 push 调用点**，于是：

- b4 的 push 循环区域从 17 条 IR 涨到 98 条（LICM 探针实测：循环区间被
  内联的 grow 体撑大，`readonly=False`、load 3→12 条）；
- 稳态下 2M 次 push 只有前几次真的扩容，其余 99.9998% 都在跳过这段大块
  死代码 —— 但它占着寄存器分配、拉长活跃区间、污染 i-cache 行。

这就是 v2.93 里"b4 从 64.8 涨到 79.6"的全部来历。**当时猜的是"函数体变大、
寄存器压力上升"（方向对），但没定位到具体哪个 callee。这一版闭环了。**

## 修法

`lower_runtime()` 里给 `__vec_grow` 打一行 `f.no_inline = True`——复用
parfor worker 已有的机制（`opt_inline` 的 `getattr(callee,"no_inline")` 闸门），
不新建启发式引擎。gaps §5 登记的"按热度分档阈值"因此不需要做了：
**真正需要的不是按热度分档，是按冷热路径分档**，一个标记解决。

## 边界

| 项 | 现状 |
|---|---|
| 其它冷路径 helper（`__vec_fail`/OOM 打印类）| 本来就 40+ 条进不了 28 档；现在 60 档下若被内联，同样亏。本版只钉了实测有害的那一个；`__vec_fail` 是调用点极稀的失败分支，暂不预加标记——等 A/B 出证据 |
| grow 自身 18 条 IR | 阈值判据仍用降级后条数；grow 若将来膨胀（如支持 vec[vec] 深拷贝）不受影响——它已被排除在内联之外 |
| qlmc（stage-1）| 无内联器，本改动不触它；`qlmc.exe` 由旧 stage-0 编出，行为不变 |
