# v3.83 — 公平性能对比工具 + `b1_int` 差距定位（一次负结果）

- 日期：2026-11-02
- 任务：复核 §7.31（性能瓶颈），先解决"**对比口径不公平**"这个前置问题。
- 影响面：`tools/dev/perf_compare.py`（新增工具）、`docs/07-gaps.md`
- 代码改动：约 130 行（工具）+ 文档

## 发现：以前的性能对比**口径不公平**

v3.83 之前一直拿 **stage-0 的 ELF 原生运行** vs **qlmc 的 PE 走 wine** 做
对比。wine 的启动与系统调用开销会混进结果，那不是"代码质量"的差异。

新增 `tools/dev/perf_compare.py`：两边**都编成 PE、都用 wine 跑**，只比
编译器产出的代码。

## 公平对比结果

| 基准 | stage-0 | qlmc | 比值 |
|---|---|---|---|
| `b1_int` | 65.9 ms | 100.7 ms | **1.53× 慢** |
| `b2_float` | 103.5 ms | 82.3 ms | **0.79× 快** |
| `b7_sort` | 99.9 ms | 56.7 ms | **0.57× 快** |
| `b9_json` | 79.9 ms | 110.8 ms | **1.39× 慢** |

**qlmc 在浮点与排序上明显更快**（f64 住 XMM、v2.55 的第二寄存器文件），
在整数与 JSON 上更慢。所以"qlmc 全面落后"这个印象是**错的**，之前的口径
把它夸大了。

## `b1_int` 的 1.53× 差距定位到两条

机器码对比（`dumpasm.py --diff` + 手工解码）：

**stage-0 循环体（7 条，条件减用 `cmovns` 无分支）**：

```asm
mov    rsi, rdi
add    rdi, 7
mov    rax, rdi
sub    rax, 13
cmovns rdi, rax        ← 无分支
add    rbx, rsi
add    r12, 1
```

**qlmc 循环体（9 条，条件减用 `jl` 分支）**：

```asm
mov  r8, rsi           ← 多余！分配器多出来的一次复制
add  r12, r8           ← 应为 add r12, rsi
add  r13, 1
add  rsi, 7
cmp  rsi, 13
jl   +4
sub  rsi, 13
jmp  loop
```

差距有两处：

1. **多一条 `mov r8, rsi`** —— 分配器在"加法点"和"自增点"给同一个 vreg
   （中间值）用了**不同寄存器**（r8 vs rsi），加法前要复制一次。
2. **条件减用分支而不是 `cmov`** —— 这是 v2.88 **有意**保留的：无分支版要
   多两个临时值，b1 的寄存器池（7 个）不够会溢出到帧槽，实测慢 6.6 倍。
   **b1 是延迟敏感型，b8 是吞吐型**，同一个变换在两边方向相反。

## 试过但失败的优化（已回退）

让 `_mod_ind_apply` 的计数器直接复用 `dst`（省掉 `MOV dst, v` 一条）：

* IR 层确实少一条（`MOV` 变 NOP，循环体 7 → 6 条）；
* **实测无改善**（新旧都是约 97 ms）；
* 原因：寄存器从 `esi`（不需要 REX）换成了 `r8`（需要 REX），指令变长 1 字节，
  抵消了省下的那条。

**收益为零、风险非零 → 回退。** 这是一次明确的负结果，记下来免得下次重试。

## 下一步（未做）

要真正收掉那 1.53×，需要改**分配器的溢出/复制决策** —— 让跨调用区间的值尽量
不产生复制。那是核心路径，必须先建"寄存器分配正确性判据"（类似 `s26_alias`
的针对性夹具），否则改错的代价远高于收益。

## 用法

```bash
python tools/dev/perf_compare.py               # 默认 4 个基准 x 3 次
python tools/dev/perf_compare.py --reps 5
python tools/dev/perf_compare.py --only b1_int b9_json
```

口径：每个基准自己打印纳秒耗时（不含进程创建），跑 N 次取最小值；
**校验和必须两边一致**，不同就判 FAIL 且不看时间。
