# v4.110 — `b28` 的 `imul` 卡在支配关系分析，不是失效策略

- 日期：2026-11-11
- 任务：消掉 `b28_matrix` 内层循环重复的 `r*n`（2 个多余 imul）
- 影响面：文档（改动全部撤回）

## 一句话

把上一轮"下一轮的确切动作"全部做完了，**但 `imul` 一个都没少**。
原因也查清了：阻断面不是失效策略、不是越界检查，而是**一个无法安全跨越的
基本块标签**，跨越它需要支配关系分析。

## 做了什么（三处改动同时生效）

1. **修 `old_vn` 取值顺序**（v4.109 记录的洞）：先记写之前的旧值编号，
   失效循环用旧值比对，**传播移到失效之后**。
2. **精确失效**：取代"写任何变量就清整表"，改为"表项的值编号 == `old_vn`
   或 == `dst`"才丢弃。
3. **越界检查四连透明**：`JCMPVLEN / LAB fail / JMP trap / LAB ok`
   整体不清表（正常路径零副作用）。

正确性：`b49_floyd`/`b75`/`b28`/`b35`/`b23`/`b11` 与最小复现 `q2` 全部正确
（除下述组合下的 `b49`）。

**但 `b28` 的 `imul` 始终是 3 个，热循环始终 32 条，一次都没变。**

## 为什么 `imul` 减不下来 —— 完整清表日志

在 CSE 里打印每一次清表，`b28` 内层循环（`i=250..300`）的记录是：

```
i=250 op=12  LAB          ← 外层循环体起点
i=251 op=25
i=254 op=12  LAB          ← k 循环头
i=255 op=25
i=256 op=5   MUL r*n      ← 第 1 处（入表）
i=258 op=73  JCMPVLEN     ← 越界检查
i=259 op=12  LAB fail     ┐
i=260 op=13  JMP trap     ├ 透明化后不清表
i=261 op=12  LAB ok       ┘
i=269 op=12  LAB          ← **真正的阻断点**
i=270 op=25
i=271 op=5   MUL r*n      ← 第 2 处（表已空，错过第 1 处）
```

`i=269` 的 `LAB` 是**内层循环体内部的一个标签**（`imm=17`）。
它到 `i=271` 之间没有回边，所以 `r*n` 在这段内确实不变 —— 但 CSE 不能
假设"执行流一定线性经过 `i=269`"：**任何 `JMP` 都可能直接跳到这个标签**，
那时寄存器里的值可能与 `i=256` 处完全不同。

要安全跨过它，必须证明"`i=269` 这个标签只有顺序落入一种入口"
（即支配关系分析）。这不是失效策略能解决的。

## 上一轮的判断修正

v4.109 我写"真正阻断是保守失效"。**这轮证明不对**：精确失效实现了、
`old_vn` 顺序也修了，`i=269` 的 LAB 照样清表。

真正的位置是：**CSE 是单基本块内的分析，而 `b28` 的两次 `r*n` 被一个
基本块标签隔开。** 这属于"要不要做支配树"的决策，不是修 bug。

## 一个附带发现：三处改动同时开会让 `b49_floyd` 变 0

单独开精确失效（不改 `old_vn` 顺序）+ 越界透明 → `b49` = 0。
说明"越界透明"和"精确失效"组合起来有语义漏洞（单独用各自的正确性都过）。

按纪律，组合有未知错误就整体不留在树上，所以三处全部撤回。

## 下一轮的判断依据

`b28` 的收益上限是 **2 个 imul**（32 条 → 30 条，约 6% 的循环指令）。
代价是做支配树/可达性分析，那是个大工程，而 `b28` 的主要浪费其实是
**4 次 store→load 往返 + 5 条冗余 mov（占 41%）**，不是 imul。

**建议下一轮转向寄存器溢出**（`asm_audit` 显示 41% 浪费在那里），
而不是继续追 imul。或者换一个基准（比如 `b17_bubble` 的检查放在别处）。
