# v4.14 — 降级期 `_vec_field` 缓存（从源头消除重复 vec 头加载）

- 日期：2026-11-04
- 任务：CSE（IR 层优化）4 次尝试都破坏正确性，改从**降级期**消除重复。
- **结论：安全生效**，内层循环 LOAD 指令数从 5 降到 4。

## 为什么换策略

IR 层 CSE（v4.06/v4.09/v4.14 三轮 4 种实现）全部破坏正确性：
合并后 `vend`（活跃区间）未更新 → 分配器复用寄存器 → 校验和错误。
即使是"只合并相邻 NOP 之间的重复"也出错。

**降级期缓存**完全不同：不修改 IR，只在生成 IR 时复用已有值。
没有活跃区间问题、没有分配器问题。

## 做法

`_vec_field(fc, h, off)` 在生成 `ADDRF + LOAD` 之前，先反向扫 IR
找最近的 `ADDRF h, off` + `LOAD`（降级期的固定两指令模式）。
若中间无 STORE/CALL/写 `h`，直接返回已有的 LOAD 结果。

匹配逻辑：在 `ADDRF` 处看**下一条**（`k+1`）是否为 `LOAD a == ADDRF.dst`。
（反向扫描时 `LOAD` 在 `ADDRF` 之前被看到，所以必须从 `ADDRF` 处向前看。）

## 效果

`b28_matrix` 内层循环：5 个 LOAD → **4 个**（消除了 c 的重复 data 指针加载）。

| 基准 | 校验和 | 计时 |
|---|---|---|
| `b28_matrix` | 960991321 ✅ | 803ms |
| `b23_lcs` | 1498 ✅ | 99ms |
| `b22_knapsack` | 9750 ✅ | 24ms |
| `b1_int` | 119999988 ✅ | 68ms |

## 性能收益有限的原因

消除的那条 LOAD 本来就会被分配器优化掉（值在寄存器里复用）。
真正的瓶颈是**冗余越界检查**和**寄存器溢出**，不是重复 LOAD。
下一步应该攻这两个。
