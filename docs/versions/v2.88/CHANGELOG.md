# v2.88 — 无分支回绕：**负结果**（b1 慢 6.6×），已回退

- 日期：2026-10-27
- 任务：性能 —— 试"回绕无分支化"（v2.87 CHANGELOG 里点名的下一顺位）
- 结论：**不采纳**。b8 只快 2~3%，b1 慢 6.6×。回退，只留下两处稳健性修复。

## 试了什么

v2.87 的归纳削减用条件减做回绕：

```
v += step
if v >= D { v -= D }        ; cmp + jl + sub，每轮一条 taken branch
```

v2.87 只让 b8 快了 13%，我判断瓶颈是"回绕的 `jl` + 循环回边"两条 taken
branch，于是换成纯算术：

```
t = v - D
m = t >> 63          ; t < D 时 m = -1，否则 0
m = m & D            ; t < D 时 m = D
v = t + m
```

语义与条件减完全等价（`v += step` 后 `v < 2D`，一次减就够）。

## 实测（本机 min of 3，新旧产物交替）

| 基准 | 条件减（v2.87） | 无分支 | 结论 |
|---|---|---|---|
| b8_threads1 | 278 / 287 / 292 ms | 273 / 279 / 282 ms | **快 2~3%** |
| b1_int | 21.0 / 23.5 ms | **138.1 / 138.5 ms** | **慢 6.6×** |

## 为什么

**它要多两个临时值。** b1 的 `main` 里同时活着 `n`/`acc`/`i`/`v`/`tv`/`mv`，
而变量寄存器池只有 7 个（RBX + R12-R15 + RSI + RDI）——`tv`/`mv` 被挤到帧槽，
热循环里凭空多出两次访存。b8 的 `work` 变量少，挤得下，所以只是略快。

更一般地说：**b1 是延迟敏感型**（循环携带链 `v → v` 决定速度），**b8 是吞吐型**
（160M 次迭代，指令条数决定速度）。同一个变换在两边方向相反 —— 这类"多几条
算术换掉一条分支"的改写，只有在寄存器充足时才划算。

条件减版本在 13 周期的模式上分支预测得很好（TAGE 完全学得会），所以
"少一条 taken branch"本来就不是瓶颈。我上一轮的判断是错的。

## 留下的两处修复（与性能无关，是稳健性）

调试过程中撞到两个优化层的隐患，都修了：

1. **优化层新建 vreg 后，`cok`/`cval`/`use`/`ndef` 四张表没跟着长**。
   它们是按 `_opt` 进入时的 vreg 数开的，而 `_opt_copy` / `_opt_fuse` 里有
   `use.get(d)` 没做上界检查 —— 一旦优化层自己 `_vnew` 出新值，就是
   `vec index out of bounds`。现在 `_mod_ind_apply` 之后统一补齐。
2. **`_vnew` 的活跃区间是"半成品"**（vstart = 当前长度、vend = 0）。
   优化层新建的临时值必须自己写 `vstart`/`vend`，否则线性扫描分配器拿到
   倒挂区间。现在代码里写明了这一点。

这两条以前不会触发（优化层从不新建临时值），但任何"往 IR 里加算术"的优化
都会踩到 —— 所以修的是**给下一个优化铺路**，不是给这一版。

## 下一轮该往哪走

b8 的 3.41×（对 C）剩下的是"每轮 9~10 条指令 + 2 条 taken branch"，C 那边是
AVX2 向量化（48 条/16 元素）。**继续在标量层面抠已经接近边际**，真正的杠杆是：

1. **循环展开 2×**（把回边摊薄一半）—— 便宜，对吞吐型循环有效；
2. **寄存器压力**：变量池只有 7 个，b1 这类多变量循环挤不下 —— 这是 b1/b8
   共同的隐性上限；
3. **自动向量化**（识别计数循环 + 归约）—— 追 C 的唯一办法，但那是新一层机器。
