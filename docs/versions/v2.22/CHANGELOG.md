## 主事件：切片 = `(ptr, len)` 两字视图

| 能力 | 做法 |
|---|---|
| `[]T` 类型 | `TY_SLICE + elem`；值 = 16 字节聚合 `[ptr][len]`，与 struct 共用"值 = 区域地址"的表示 |
| `a[lo..hi]` | 数组 / vec / 切片都能切；结果是一个视图（**不拷贝**，与原容器共享内存） |
| `s[i]` 读 / 写 | 先按 `len` 查边界（无符号比较，负数也拦），再用 `ptr + i*8` 存取 |
| 切片再切片 | `s[1..3]`：从 `s` 的 ptr 再偏移，视图套视图 |
| 作形参 | 走 v2.20 的聚合 ABI（按值传 16 字节 + 被调方拷贝） |
| `len(s)` | 读 `[len]` |

边界：`lo <= hi <= 源长度` 在**创建视图时**检查，越界 `exit(1)`；元素下标越界同样 `exit(1)`。
别名语义与 stage-0 一致：通过切片写会改到原数组（`s[1] = 99` 之后 `a[2] == 99`）。

## 踩到的坑：类型编码区间重叠

`TY_SLICE = 0x20000` 落在 `TY_VEC(0x8000) .. TY_ARRAY(0x100000)` 区间里，于是
`_addr_index` 里"是不是 vec 下标"的判断**先把切片抓走了**——它把切片当成 vec 句柄，
读 `[切片地址]`（也就是 `ptr`）当长度，算出一个"元素地址"直接返回（类型还标成了聚合），
于是 `s[0]` 打印出的是一个指针值。

修法：vec 分支的上界从 `TY_ARRAY` 收到 `TY_MAP`，并让切片分支排在前面。**类型编码
按区间判定时，区间必须互不重叠**——这条已写进坑表。

## 已知边界

- 切片元素限 int/bool/str（聚合元素暂不支持）；**数组不能隐式转切片**（要写 `a[0..n]`）。
- 切片不拷贝：生命周期由程序员负责（`07-gaps` 里记着"视图逃逸"检查是 stage-0 的活）。
- 仍缺：f64、泛型、闭包、`defer`、`import`、宏/反射、`@ffi`、接口、`rc`；
  vec/map 仍固定容量。
