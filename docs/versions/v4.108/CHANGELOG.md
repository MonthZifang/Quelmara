# v4.108 — CSE 终于可用：值编号解决自举不动点

- 日期：2026-11-11
- 任务：让 v4.93 撤回、v4.107 卡住的 CSE 真正合入
- 影响面：编译器（优化器 pass）

## 一句话

**CSE 合入了** —— 76/76 checksum 一致 **且** 自举两代逐字节不动点成立。
性能持平（76 项 +0.03%，噪声内），但拿回了正确性与稳定性。

## 三轮才修好的 CSE

| 轮次 | 查到的根因 | 结果 |
|---|---|---|
| v4.93 | 以为是键冲突 | checksum 变 0，撤回 |
| v4.106 | **改了 IR 没更新 `use[]`** | `b49_floyd` 修好（0→173），`b75` 仍错 |
| v4.107 | **变量赋值没让表失效**（同一变量多个 vreg） | 76/76 全过，但**不动点不收敛** |

### v4.107 的死结

同一个修复，带 `eprint` 诊断的版本自举收敛（E2 == E3），
把诊断删掉就**不收敛**（C2 ≠ C3，差 17888 字节）。

差别的只有几行 `eprint`。原因是 CSE 的键是
`(op, a, b, imm)` —— **`a`/`b` 是 vreg 编号**。而 vreg 编号的分配顺序
取决于前面 pass 产生了多少临时值：多几行诊断代码 → 多几个临时值 →
编号整体偏移 → 同样的表达式命中不同的 CSE 决策 → 产物不同。

对自举语言这是**致命的**：不动点要求三代产物逐字节相同。

### v4.108 的修法：值编号（value numbering）

给每个 vreg 记一个"值编号"，表达式的键用**操作数的值编号**而不是 vreg 号：

```qma
// 初始：每个 vreg 的值编号等于它自己
vn[i] = i

// 遇到 `MOV d, a`：d 与 a 同值，值编号跟随
vn.set(d, vn.get(a))

// 遇到别的写指令：d 变成新值，编号回到它自己
vn.set(d, d)

// 键改用 vn.get(a) / vn.get(b)
```

这样**穿过任意多层 MOV 也能认出同一表达式**，而且键与 vreg 编号的
绝对数值无关 —— 编号整体偏移不再影响决策。

### 三处配合修改

1. **键用值编号**（`va`/`vb`）
2. **`MOV` 传播值编号**，其他写指令重置
3. **命中时同步维护 `use[]`**（v4.106 的结论）与值编号

加上 v4.107 验证过的保守失效：**写任何 `vpin != 0` 的变量就清空整表**
（因为表达式操作数可能是同一变量的另一个 vreg，逐项比对编号抓不到）。

## 值编号没有带来预期的 `b28` 收益

原以为值编号能合并 `b28_matrix` 里三个 `r*n`。实测 **imul 只从 32 降到 31**。

原因：三次 `r*n` 求值时 `r` 和 `n` 是**新读出的临时值**，它们之间没有
`MOV` 链，所以值编号各不相同。要合并它们需要**识别"同一个变量"**
（`E_VAR` 每次求值都新建 vreg，但逻辑上是同一内存位置）——
那需要把 `vn` 建立在变量身份而非 vreg 之上，是下一步。

## 代价与收益的诚实评估

- **收益**：拿回一个正确的公共子表达式消除。命中时消掉重复计算
  （`b35_branch` 里 `(i & 3)` 从 3 处减到 1 处）。
- **代价**：保守失效（写变量就清表）让命中率不高，所以总耗时持平。
- **价值主要在正确性**：CSE 是后续更强优化（值编号推广、循环不变量、
  自动向量化）的基础设施，之前它不可信，现在可信了。

## 已知边界 / 遗留

- 保守失效让命中率偏低。更精确的做法是建立**别名分析**，
  判断"写变量 X 是否影响表达式 E"，而不是一律清表。
- 值编号基于 vreg 而非变量身份，所以跨 `E_VAR` 求值的相同表达式认不出。
- 只在单个基本块内生效，跨块需要支配树。
