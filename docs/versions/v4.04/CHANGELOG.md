# v4.04 — 尝试把 vec data 指针提出循环（**负结果**，已回退）

- 日期：2026-11-04
- 任务：`b28_matrix`（13×）/ `b23_lcs`（9.5×）落后最多，两者都是纯数组
  访存，差距来自"每轮重读 vec 头"。
- 结论：**已回退**。定位到了三个真正的坑，但修到最后一个时仍会崩两项，
  按纪律回退。

## 目标

`b28_matrix` 的内层循环 IR：

```
294  LOADD  dst=216(s44)  a=123  b=0  imm=0   ← 读 c 的 data 指针
296  LOADX  dst=218(s45)  a=216  b=212        ← 读 c[r*n+j]
304  LOADD  dst=221(r11)  a=123  b=0  imm=0   ← **又读一次** data 指针
306  STOREX dst=203(r9)   a=221  b=201
```

`123` 是 vec 句柄（循环不变量），所以 `[123+0]` 也不变。C 那边这个指针
就住在寄存器里。

## 定位到的三个坑（都有价值）

### ① `LOADD` 是 `_opt_fuse` 融出来的，扫描必须放在它之后

第一版把 hoisting 放在 `_opt_copy` 之前。诊断显示 pass **确实进去了**、
也找到了循环，但"一条候选都没有" —— 因为那时 IR 里还是
`ADDRF + LOAD` 两条，**根本没有 `LOADD` 指令**。
`LOADD` 是 `_opt_fuse` 把 `ADDRF+LOAD` 融合出来的。
把它挪到 `_opt_fuse` 之后，立刻看到 55 条。

### ② `OP_LOADD` 的 `imm` 是**字节偏移**，不是宽度

```
imm==0  -> [v+0]  = data 指针   ← 要提的是这条
imm==8  -> [v+8]  = len
imm==16 -> [v+16] = cap
```

第一版写成 `w.imm == 8`（当成宽度），匹配的是 len —— 而 len 在循环里
通常不变、也已被别处优化，收益必然为零。

### ③ 循环回边不止 `JMP`/`JCMP`/`JCMPI`

`while` 降级后，内层循环的边界常用 `JCMPVLEN`（越界检查）表示。
只认前三种，热循环**一次都扫不到**。

## 修到哪一步、为什么还是回退

三个坑都修完后：`hoist_test`（矩阵骨架）和 `b23_lcs` **结果正确**，
但 `b28_matrix` / `b22_knapsack` **SIGSEGV**。

原因是外提后必须同步修 `dst` 的活跃区间 —— `_ir_insert` 只把 `>= at`
的 `vstart`/`vend` 整体 +1，而被搬的指令现在**定义在循环头、使用仍在
循环体内**。我按"`vstart = h`、`vend = max(vend, q+1)`"修了一版，
两项仍崩。

**按纪律回退**：收益不明（没测到正收益就先崩了）、风险明确。
`git checkout` 恢复，v4.04 只留文档。

## 下一步（给接手的人）

正确做法不是"外提单条指令"，而是**在降级期就避免重复生成**：
`_vec_field(fc, h, 0)` 每次调用都新生成 `ADDRF+LOAD`，
如果同一个 `h` 在**同一基本块**里已经取过 data，复用那个 vreg 即可。
那样根本不需要事后移指令，也就没有活跃区间问题。
