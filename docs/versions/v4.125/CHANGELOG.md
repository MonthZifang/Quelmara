# v4.125 — `x % 2^k == 0` 特化成 `x & (2^k-1)`（b13_collatz −17.1%）

- 日期：2026-11-20
- 任务：继续按"跑分最差且修得动"挑靶。v4.124 修掉 b69 之后，榜首变成
  b9_json 3.07×（ABI 演进，数周级）、b23_lcs 3.02× / b28_matrix 3.00×
  （vec 双重访存，需内联布局）。**b13_collatz 2.93× 是这一档里唯一
  属于纯优化器缺口、且能一次做完的。**

## 等价性：这是本版全部分量所在

C99 的 `%` 是截断语义：`x % 2` 对负 `x` 得 **-1**，而 `x & 1` 得 **1**。
**两者不相等** —— 只要 `%` 的结果还能被读到，就绝不能替换。

反证（本版实测的翻车）：把 `b13` 里的 `n % 2 == 0` 直接改写成
`n & 1 == 0`，程序**死循环**。因为 `n` 在 Collatz 里会走下坡再反弹，
判奇偶判反之后序列发散。

但**"和 0 比较"的结果**相等：

```
x % 2^k == 0  <=>  2^k 整除 x  <=>  x 的低 k 位全 0  <=>  x & (2^k-1) == 0
```

与符号无关，已逐值核过 `-8..8`；`!= 0` 两边同时取反同样成立。

> 所以特化的判据必须是"**这个中间值只被一条与 0 的比较读过**"，
> 而不是"这个 `%` 可以换成 `&`"。两者的区别就是死循环与正确的区别。

## 实现（`_opt_mod_zero_cmp`）

判据（全部满足才动）：

1. `OP_DIVC dst=t, a=x, b==OP_MOD, imm=d`，`d` 是 2 的幂且 `>= 2`；
2. `t` 全函数**只被写一次、只被读一次**（函数内自数，不依赖外部
   `use`/`ndef` —— 它们在 `_opt_mod_ind` 之后可能已过期）；
3. `t` 的那唯一一次读是一条与**常量 0** 比较的 `CMP`/`CMPI`/`JCMP`/`JCMPI`。

命中时 `DIVC` → `OP_BINI t, x, OP_AND, d-1`；比较指令原样保留（它比的还是 0，
只是 `t` 现在装"低 k 位"而非"截断余数"，两者**是否为零**逐值相同）。

位置：`_opt_mod_ind` 之后（归纳削减会改写 DIVC 的上下文）。

## 两个必须记住的坑

### 坑 1：`JCMPI` 的操作数位置和 `CMPI` **不一样**

```
OP_CMPI   dst=<cc>, a=vreg, b=<cc 机器码>, imm=**常量**
OP_JCMPI  dst=<cc>, a=vreg, b=**常量**,   imm=**跳转目标标签**
```

第一版对 `JCMPI` 写了 `w.imm == 0`（以为 imm 是比较值），而 imm 是标签 id，
**永远不为 0** → `n % 2 == 0` 这种最典型的条件一次都没命中，整个 pass 静默
无效。诊断打印打出 `defs=1 reads=1 zcmp=0` 才定位到。

### 坑 2：O(n²) 会打穿编译时间

第一版对每个 `DIVC` 线性扫一遍"与 0 比较"的列表。编 qlmc 自己（469 个函数、
IR 数万条）直接 **40 分钟跑不完**（`timeout 124`），被误判成"pass 太慢"。
改成按 vreg 直访的标记表（两趟线性）后才可用。

**加 pass 之前先想清楚代价是不是 O(n)。**

### 坑 3（环境）：跑飞的测试进程会伪造"我的代码很慢"

一个死循环的 Collatz 测试变体占满一个核跑了 **2 小时 32 分**，把 4 核机器
拖到 `load 4.6`，导致随后几次自举构建全部 `timeout 124`。跑会死循环的测试
一律加 `timeout`，并且跑完 `pkill` 确认。

## 验证成本的现状（重要）

`stage-0` 编 qlmc 自己在这台机器上**已经从 v4.122 的 871.5s 涨到 >2000s**
（源码 22.5k 行，469 个函数）。任何 qlmc 侧改动的"编一遍再测"循环要 20–40 分钟。

本版因此改用**旧 qlmc 编新 qlmc**（约 17 秒）来做迭代验证 —— 它也能覆盖
新 pass（优化器代码来自新源码），只是不能替代最终的自举不动点检查。
**低于 5% 的收益不值得那个 20 分钟循环**，除非能先用 stage-0 的等价改写量出上限。
