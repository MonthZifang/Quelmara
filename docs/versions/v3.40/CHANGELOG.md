## 先纠正上一版的判断

v3.39 的 CHANGELOG 写"剩余失败里 `vec[vec[T]]` 有 **4 个**模块"。
这一版按实际输出重新数，**只有 1 个**（`std/csv.qma`）：


上一版的"4"来自 v3.38 的错误分类（那时把 `vec 方法不全` 的 4 个和

这个纠正很关键，因为它改变了优先级判断：

* 若真是 4 个模块 → 值得重写类型编码（34 处比较）

所以这一版没有去做类型编码重构，改做性价比明确的项。

## 这版做的：两个零成本内建

### `str_ptr(s) -> int`

取 str 的**数据指针**。Quelmara 的 str 是长度前缀 ABI
（`[len:8][bytes...]`），而 **str 的值本身就是数据指针**（指向第一个
字节）—— `__str_len` 的实现就是 `load(p-8)`，正好印证。

所以这个内建**不分配、不复制、零成本**：直接返回操作数（一条 `OP_MOV`）。

用途：把 str 喂给 `tcp_send_n(fd, ptr, n)` 这类零拷贝内建。

### `target_arch() -> int`

编译期常量：1 = x86_64 / 2 = aarch64。qlmc 只产 x86-64 PE，所以恒为 1。

语言没有条件编译，这个内建的作用是让库层"选对常量"（syscall 编号
同时取决于 OS 与架构）。

## 夹具的设计要点

`t184_qlmc_strptr.qma` 的核心不是"能调通"，而是**钉住 ABI 约定**：

```quelmara
let s = "hello"
let p = str_ptr(s)
assert(mem_load8(p, 0) == 104)      // p[0] = 'h'
assert(mem_load64(p - 8, 0) == 5)   // 长度头在 p-8
```

这两条**配对**才有意义：证明 `str_ptr` 返回的是**数据**指针、长度在它
前面 8 字节。如果哪天有人把 str 改成"指向长度头"，`str_ptr` 会静默偏移
8 字节 —— 拿它喂 `tcp_send_n` 会发出错误的数据，而**不会崩**。

这类"依赖 ABI 约定的零成本内建"最需要断言，因为它的正确性不可从
"能跑"推出来。

## 下一步的判断

**网络内建（6 个模块）是唯一的大块**，但它需要：

1. 在 qlmc 里加 Winsock 导入（`WSAStartup` / `socket` / `bind` / `listen` /
   `accept` / `recv` / `send` / `closesocket`…）；
2. 处理 `sockaddr` 结构与 `SOCKET` 句柄（在 x86-64 上就是 8 字节整数，
   不难，但要与 stage-0 的 `std/net/core` 语义对齐）；
3. 每个内建的失败语义（返回 -1 还是 fail-fast）都要与 stage-0 一致。

那是**独立一版到两版**的工程量，且需要先摸清 stage-0 的
`std/net` 抽象（`std/net/core.qma` 的 `SLOT_*` 布局）。

**不建议**现在去碰类型编码重构 —— 它只值 1 个模块。

## 一个反复出现的流程问题

连续两版（v3.38、v3.40）都在"把判断写进文档"这一步出错，而错因相同：
**数数字/下结论时没有对着实际输出核对**。

v3.38 承认过一次（"共同缺口"没 grep 验证），这一版又犯了（模块数从 1
写成 4）。这说明"写文档前先跑一遍确认"应该成为固定动作，而不是
靠记性。
