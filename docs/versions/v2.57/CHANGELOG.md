- 日期：2026-10-26
- 任务：`b9_json`（4.6×）与 `b6_hash`（1.03×）还有明显的"指令数税"，做三处
  通用的代码质量改进
- 影响面：`bootstrap/qlmc/qlmc.qma`（新增 `OP_JCMPI` / `_opt_copy` / `_alloc` 的
  循环判定）、文档

## ① `OP_JCMPI`：条件跳转的立即数形式

`b9_json` 里最肥的一处。`jws`/`jnum` 每读一个字节都要比 `' '`/`'\t'`/`'\r'`/
`'0'`/`'9'`，而 `OP_JCMP` 只有 reg-reg 形式：

```
mov  r8d, 0x20        ← 每次比较都先装载常量
cmp  rsi, r8
jg   ...
```

`cmp` 本来就支持 imm32，一条顶两条。新增 `OP_JCMPI`（`dst` = jcc 码、
`a` = 左操作数、`b` = 常量、`imm` = 标签），优化层把"右操作数是已知常量"的
`OP_JCMP` 折过来（限 `[-2^31, 2^31-1]`，因为 `cmp r64, imm32` 会符号扩展）。

`imm8` 用 `83 /7 ib`（4 字节），否则 `81 /7 id`（7 字节）。

实测：`b9_json` 里 `mov rXd, imm` + `cmp` 的组合从 **11 处降到 0 处**，
立即数比较 21 处。

> **坑**：`b` 槽从此不是 vreg 了 —— `_opt_mark`、`_alloc_vars`、`_opt_use`
> 三处"`b` 不是 vreg"的排除表都要加 `OP_JCMPI`。漏一处就是把常量值当成
> vreg 下标去记一次"使用"，会让某个真实的值被误认为还活着（或更糟：
> 让 DCE 留下一条死指令）。

## ② `_opt_copy`：相邻拷贝传播

qlmc 的降级期"每个值都先落一个临时 vreg"（`_lower_into` 先 `_lower_expr`
再 `OP_MOV`），于是到处是纯搬运：

```
mov rax, r8           ← 调用结果搬进临时值，再搬进 rax
mov r12, rbx          ← return 的暂存
mov rax, r12
```

新增一趟 `_opt_copy`：`OP_MOV d, a` 后面紧跟**唯一**读 `d` 的那条指令时，
把那条指令的读操作数换成 `a`，MOV 消成 NOP。

三条安全边界（缺一不可）：

1. `d` 必须是**单定义、单使用**的临时值（不是变量、不是聚合）；
2. **只换 `a`/`b` 这两个只读操作数** —— `dst` 绝不能动：`x = x op y` 里
   dst 也是被读的，换了就错；
3. 读 `d` 的那条指令不能同时写 `d`。

放在 `_opt_fuse` **之前**：先消搬运，融合看到的形状更干净。

## ③ 循环里跨调用的临时值 → 空着的 callee-saved 寄存器

`_alloc` 以前对"区间跨调用"的临时值一律溢出到帧槽。但"变量没占满 7 个
callee-saved 寄存器"是常态（`fib` 只有 1 个参数），空着的 `RBX`/`R12-R15`/
`RSI`/`RDI` 白放着。

现在：**区间跨调用 且 落在循环体内**的临时值，先试空着的 callee-saved 寄存器。
序言/尾声的 push/pop 由 `_emit_fn` 从 `vloc` 自动推出，不用另记。

**为什么限定"循环内"**：溢出是**每次执行**两条内存往返，占用一个
callee-saved 只是**每函数一次** push/pop。循环外只溢出一次，换寄存器反而
白搭一对 push/pop —— 实测 `fib` 因此慢 4.7%，所以加了循环判定。

循环覆盖用差分数组 + 前缀和算（`OP_JMP`/`OP_JZ`/`OP_JNZ`/`OP_JCMP*` 的
目标下标 < 自身下标即为回边）。
