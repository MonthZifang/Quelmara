## 踩到的两个语法坑

* `(2*i+1).to_f64()` **不存在** —— f64 转换要用 `to_float(x)`（自由函数，
  不是方法）。`to_int()` 是 `str` 的方法，f64 没有对应方法。
  所以 `b16_leibniz` 直接打印 `pi`（三语言都用 `%.6f` / `print(pi)`），
  不绕"转成整数再比"那道弯。

## 一条**没有**采纳的优化（重要）

`b26_maxsub` 的 `(seed * 1103515245 + 12345) % 2147483648` 让 qlmc 慢到
**4.25×**，而 C 只要 1.00×。原因是 `2147483648`（2^31）超出 `OP_DIVC` 的
`imm32` 范围，落回通用 `idiv`（~30 周期）。

实验确认了这一点：把基准里的 `% 2147483648` 换成 `& 2147483647` 之后，
qlmc 从 950 ms 降到 376 ms（4.25× → 1.67×）。

**但没有把 `x % 2^k → x & (2^k-1)` 加进编译器**，因为它**不总是等价**：

* 对**非负** x，`x % 2^k == x & (2^k-1)`；
* 对**负** x，两者不同（x86 的 `AND` 取低位，而语言语义要的是负余数）。

`b26_maxsub` 里 `seed * 1103515245` 会溢出成负数，**正好落在不等价区间**。
v2.46 有过"把 `% 13` 变成 `+ 13`"的静默错值事故，这里不重蹈。

**正确做法（待做）**：
```
t = x & (2^k - 1)          ; 低位
t += (x >> 63) & (2^k)     ; 负数补回模数
```
3 条指令，仍远快于 `idiv`，且对正负都等价。登记为后续优化项。
