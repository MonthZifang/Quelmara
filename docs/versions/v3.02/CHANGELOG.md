# v3.02 — 寄存器池扩到 11（+RCX/RDX）：正确但更慢，已回退

- 日期：2026-10-29
- 任务：性能 —— 按 `07-gaps.md` §5 登记的"寄存器池扩到 11"，先做隐式寄存器审计
- 影响面：无（**代码已回退**）；文档登记负结果 + 三项审计结论

## 动机

`b9_json` 的 `jval` 有 **198 个 vreg / 24 个溢出槽**，而 caller-saved 只用
了 `RSI/RDI/R8/R9` 四个。直觉上多两个寄存器（`RCX`/`RDX`）就该少一堆
内存往返。缺口文档登记的前置是：**先审计隐式寄存器占用**。

## 审计：三项隐式占用（这部分结论是有价值的）

扩大池之前必须说清"哪些寄存器会被指令偷偷用掉"。逐条查发射器：

| 指令 | 隐式占用 | 证据 |
|---|---|---|
| 变量移位 `x << n`（n 非立即数） | **CL（RCX）** | `rb = self.fetch(RCX, src_b)` → `mov_rr(RCX, rb)` → `shift_cl` |
| `div` / `mod` | **RDX:RAX** | `cqo()` 写 RDX、`idiv(rb)` 读 RDX:RAX 写 RAX/RDX |
| `umulhi` | **RDX:RAX** | `mul_u(rb)` → `rdx:rax = rax * rb` |
| `cpuid_sha/aes/pclmul` | **RAX/RBX/RCX/RDX 四个全毁** | 发射器 push/pop 四个寄存器 |

结论：**RCX/RDX 可以进池，但分配器必须按指令类别避让**。

## 实现

1. 新增 `_implicit_clash(fn, i)`：返回该指令会踩掉的寄存器集合，
   只在真会踩的指令上返回非空。
2. 分配器在选出 `candidates` 之后，对**该 vreg 的活跃区间**逐指令扫一遍，
   把区间内被踩的寄存器剔掉。
3. 池从 9 扩到 11（`POOL_WIDE`）。

**正确性全过**：10 个基准的校验和与改动前逐字节一致，包括此前循环旋转
实验里崩掉的 `b9_json`（`4010000` 正常）。回归也在跑。

## 但速度没赢：第一次还写反了

### 第一版：池顺序写错，全面变慢

第一版把 `RCX/RDX` 放在池的**最前面**。分配器对"不跨调用"的值优先挑
caller-saved（省掉被调用者的 push/pop），于是原本落在 callee-saved 上的
长寿命值被挤到 caller-saved，跨调用时反而多付保存代价：

| 基准 | 窄池（9） | 宽池第一版 | 变化 |
|---|---|---|---|
| b9_json | 76.3 ms | 87.5 ms | **慢 15%** |
| b7_sort | 96.3 ms | 104.0 ms | 慢 8% |

### 第二版：顺序修正（RCX/RDX 排最后），仍无收益

| 基准 | 窄池（9） | 宽池（11，顺序正确） | 变化 |
|---|---|---|---|
| b9_json | 76.1 / 76.3 / 76.4 ms | 76.0 / 76.1 / 76.2 ms | **持平** |
| b7_sort（7 次中位） | **104.8 ms** | **126.9 ms** | **慢 21%** |

b7 的 7 次原始读数（ms）：

```
宽池：167.1 139.3 126.9 128.9 101.5 101.4 101.7   中位 126.9
窄池：110.9 104.8  99.3 131.5 135.7  99.6 102.1   中位 104.8
```

## 为什么没赢（比"再调一版"更重要的判断）

正确性没问题、避让也没写错，**收益被两件事吃掉了**：

1. **b9 的 24 个溢出槽本来就不在热路径上**。`jval` 是个大 switch，溢出的是
   各分支里的短命临时值——它们溢出到栈、下一条指令立刻读回，但**每条只发生
   一次**，不是循环里的重复往返。多给两个寄存器，省的是这些一次性往返。
2. **更多可用寄存器 ⇒ 更长的活跃区间**。线性扫描在寄存器充裕时会延长值的
   存活（不急着溢出），于是跨调用的活跃值变多，`push/pop` 变多。b7 是
   **递归 quicksort**，每次递归调用都要重排一遍，caller-saved 变多直接抬高
   每次递归的保存成本——这正是它慢 21% 的来源。

## 结论：回退，并登记"扩池不是杠杆"

项目铁律（`07-gaps.md` §5 末尾）：

> 前置条件不满足就回滚并登记重启条件；错误代码比没有代码更糟。

这次的证据很干净：**正确性全过、b9 持平、b7 慢 21%**。留着只会让 b7 变慢
并让分配器背上一套"逐指令扫区间"的开销。

**重启条件**（已写进 `07-gaps.md` §5）：先建**溢出代价模型**——按区间长度
与所在基本块的热度加权，让分配器知道"溢出一个热循环里的值"和"溢出一个
大 switch 分支里的一次性临时"代价不同。在那之前，单纯加寄存器不是杠杆。
