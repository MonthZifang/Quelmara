## 一句话

`b75_fib_matrix`），**但自举不动点不收敛**，因此不合入。

## 修好了什么

上一轮定位到第一层根因（CSE 改了 IR 没更新 `use[]`）。本轮继续挖，找到了
**第二层根因**：

### 根因：变量赋值没有让 CSE 表失效

CSE 的失效逻辑是"表项的 `a`/`b` 等于被写的 vreg 时丢弃该项"。但**同一个
变量在 IR 里可能有多个 vreg**（每次 `E_VAR` 求值都可能新建），所以
`a2 = v` 这条 `MOV` 的 `ins.dst` 与表项里记的 `ka` 不一定是同一个编号。

用最小用例复现（`/tmp/q2.qma`）：

```qma
while n > 0 {
    if n % 2 == 1 {
        let v = (a2 * a1 + a3 * a3) % 1000003
        let w = (a2 * a1 + a3 * a3) % 1000003   // 与 v 完全相同的表达式
        a2 = v
        a3 = w
    }
    let b3 = (a2 * a1 + a3 * a3) % 1000003      // 块外，表达式又相同
    a2 = b2 ; a3 = b3
    n = n / 2
}
```

输出对比：

| 版本 | `a2` | `a3` | 期望 |
|---|---|---|---|
| 基线 | 1806 | 1806 | ✓ |
| CSE（未修） | 30 | 22 | ✗ |
| CSE（本轮修法） | 1806 | 1806 | ✓ |

`a2 = v` / `a3 = w` 之后，表里的 `(MUL, a2, a1)` / `(MUL, a3, a3)` 必须失效，
但因为是不同 vreg 编号，失效没命中 —— 块外的 `b3` 复用了块内的旧值。

### 修法：写变量就清空整表（保守）

```qma
// 只要写了任何 vpin!=0 的变量，整表清空
if ins.dst > 0 && _opt_writes(ins.op) == 1 && fc.vpin.get(ins.dst) != 0 {
    keys.clear()
    vals.clear()
}
```

比逐项失效保守，但**正确**：变量赋值可能改变任意表达式的值，因为表达式的
操作数可能是同一变量的另一个 vreg。

### 不动点为什么不收敛（本轮最有价值的发现）

- `/tmp/out/E1.exe`（带诊断的版本）自举链**收敛**：E1 → E2，E2 == E3。
- `/tmp/out/C1.exe`（清掉诊断后）自举链**不收敛**：C1 != C2，且 C2 != C3
  差 17888 字节。

两者只差几行 `eprint` 诊断代码。说明 **CSE 的决策依赖代码布局**：

CSE 的键是 `(op, a, b, imm)` 里的 **vreg 编号**。而 vreg 编号的分配顺序
依赖前面的 pass（常量折叠、JCMPI 融合等）产生了多少临时值 —— 加几行诊断
代码就改变了编号，于是**同样的表达式在两次自举中命中不同的 CSE 决策**，
产物因此不同。

这不是"错"，但对自举语言是**致命的**：不动点要求三代产物逐字节相同。

## 下一轮的方向（已经很清楚）

CSE 必须改成**与 vreg 编号无关**的判据，两个可选路线：

### 路线 A：值编号（value numbering）

给每个表达式算一个**规范化编号**（基于操作数编号递归计算，而不是 vreg 号）。
同编号的表达式必然同值。这同时能解决另一件事：`b28_matrix` 里三个
`r*n` 现在算三次，值编号能合并成一个。

### 路线 B：只做"紧邻复用"

只在**同一基本块内、两条相同表达式之间没有任何指令写操作数**时才复用。
判据变成"从上一处定义扫到当前位置"，不依赖 vreg 编号语义 —— 但仍是
基于编号比对，本质问题不变。

**建议路线 A**：值编号是从根本上解决，而且顺带能拿到 `b28` 的 `imul` 收益。
代价是要维护一张"表达式 → 编号"的表，并且编号要在每个基本块边界重置。

## 顺带修正上一轮的一个错误记录

v4.106 里我写"`cwd` 会让编译假失败"，本轮又遇到一次：`-o /tmp/C1.exe`

`/tmp` 权限或 wine 的路径处理）。**规矩：产物写到 `/tmp` 的子目录**。
