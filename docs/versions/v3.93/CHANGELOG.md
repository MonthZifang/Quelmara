# v3.93 — 第三次负结果：冷变量踢回栈槽（`b9_json` 只快 0.02×，`b1_int` 退化 0.10×）

- 日期：2026-11-03
- 任务：收 §7.31 剩下的 `b9_json` 1.28×。
- 结论：**不采纳，已回退**。这是 v2.88 之后同一机制的第三次复现。
- 影响面：`docs/07-gaps.md`（§7.31 记负结果）、`docs/06-status.md`（§3.131）
- 代码改动：**无**（试过 25 行，全回退）

## 定位

先确认差距在哪：**qlmc 的 `jws` push 7 个 callee-saved，stage-0 只 push 3 个**。

内循环体两边**逐条相同**：

```asm
movzbq 0x0(%rbx,%r14,1),%r9
cmp    $0x20,%r9 ; je  →  加一
cmp    $0x9,%r9  ; je  →  加一
cmp    $0xa,%r9  ; je  →  加一
cmp    $0xd,%r9  ; jne →  退出
add    $0x1,%r14
jmp    loop
```

所以差距**全在 prologue/epilogue**：每个被占用的寄存器一来一回 2 条指令，
每 token 差 8 条。

`jws` 有 6 个变量、寄存器池是 7 个，于是全进了寄存器。其中：

* `p0` —— 拷进局部 `p` 之后**再也不碰**，只用一次；
* `c` —— 读一次、比完就丢，只用一次。

**只用一次的变量占着 callee-saved 是纯浪费**：寄存器版要 2 条 push/pop，
栈槽版每次访问 1 条访存。1 条 < 2 条。

## 实现与实测

在 `_alloc_vars` 的贪心交换**之前**加一段：把 `ucnt <= 1` 的标量从寄存器
踢回帧槽（`_st_units` 拿新槽）。

`jws` 的 push 确实从 **7 降到 3**（rbx / r14 / rsi + rbp），帧从 0x28 涨到 0x48。

| 基准 | v3.92 | v3.93 | 结论 |
|---|---|---|---|
| `b9_json` | 1.28× | **1.26×** | 只快 **0.02×** |
| `b1_int` | **0.93×（快）** | **1.03×（慢）** | **退化 0.10×** |
| `b7_sort` | 0.58× | 0.60× | 退化 |
| `b2_float` | 0.80× | 0.79× | 噪声内 |

## 为什么失败

**踢出去的变量在循环里多了访存，收益被吃掉。** `jws` 的 `go` 被踢到
`-0x18(%rbp)` 之后，循环里 `while go == 1` 那步从"读寄存器"变成"读内存"，
正好抵消了省下的 push。

而 `b1_int` 那种**延迟敏感**的循环（`v → v` 循环携带链）直接被访存打回慢。

**这是 v2.88（无分支回绕慢 6.6×）之后同一个机制的第三次复现**：

> **寄存器池紧张时，"省一条 push" 换 "循环里多一次访存" 永远不划算。**

## 已回退

按 v3.83 的先例（"收益为零、风险非零 → 回退"），这次是"收益 0.02×、
另一项退化 0.10×、风险非零"，更没有理由留。

## 剩下的路

只剩**内联器**（每 token 一次调用 → 零次）。它是 IR 拼接 + 变量重编号 +
标签重映射 + 活跃区间重建，是另一个量级的工程；而控制流变换正是
v3.84（`flag_loop` 改错）和 v3.90（`CSUBNS` 帧顶爆）两次翻车的地方。

**当前判断：收益（1.26× → 可能 1.0×）与风险不匹配，暂不做。**
§7.31 到此为止 —— 它的 (a)(b)(c)(d) 全部有结论，(a) 甚至反转成 qlmc 更快。
