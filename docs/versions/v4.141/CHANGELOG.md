# v4.141 — 放宽 load-hoist 寄存器压力闸 3→4（b79_binary_tree −12.3%）

- 日期：2026-11-26
- 任务：v4.116 的 `_opt_load_hoist` 有个**寄存器压力闸** `dcnt > 3`（循环体内
  不同临时值种类数 > 3 就放弃外提），依据是"提多了把循环自己的临时值挤去溢出
  （实测 b28/b18/b22 慢 2.4 倍）"。但那条结论是**一次全放开**（不限 dcnt）导致
  的。本版把阈值精确放到 **4**，并用 diff 逐一验收。
- 影响面：编译器（stage-1 优化 pass `_opt_load_hoist` 的闸门，不改 IR 语义）

## 动机

b79_binary_tree 内层搜索循环每轮重复 `LOADD [vec+8]`（读 len）**3 次**，本可
外提一次。但该循环有 4 个不同临时值（vreg 49/51/53/56），被 `dcnt > 3` 挡住。
b79 CI 比值 3.56×、绝对 976ms，是剩余最大项之一。

## 改动

`_load_hoist_one` 的 `if dcnt > 3 { continue }` → `if dcnt > 4 { continue }`
（单行阈值 + 注释说明精确依据）。

## 收益（本机 min-of-3，v4.140 → 本版）

| 基准 | v4.140 | 本版 | 比值 |
|---|---|---|---|
| **b79_binary_tree** | 3652.3ms | **3205.1ms** | **0.878（−12.3%）** |

**回归验收**（v4.116 记录的三个受害基准，逐项 diff）：

| 基准 | 比值 |
|---|---|
| b28_matrix | 0.9987（无回退） |
| b18_insertion | 1.0002（无回退） |
| b22_knapsack | 0.9968（无回退） |
| b23_lcs | 1.0003（无回退） |

即：**只有 dcnt 恰为 4 的循环受益，dcnt>4 的仍被挡住** —— v4.116 的 2.4× 灾难
来自"完全放开"，不是"放到 4"。

## 已知边界 / 遗留

- 阈值 4 是**实测**得出的：3 会漏掉 b79 这种 dcnt=4 的循环，>4 未验证。
  换微架构时应重测（与 v4.116 的告诫一致）。
- 只改闸门数值，不动外提逻辑本身（单次一条、`vend` 延长、寄存器压力语义均不变）。
- CI 权威基准待推送后实测。
