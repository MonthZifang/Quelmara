# v2.64 — int→str 的取位循环不再用 idiv（b5_string 快 2.2×）

- 日期：2026-10-26
- 任务：继续优化性能，要求"效果突出"
- 影响面：`tools/stage0/qlm_native.py`（`_emit_divmod10` + 两个取位循环）
- 夹具：`tests/t147_itoa_magic.qma`

## 根因：一次 int→str 是「位数」次 **两次** idiv

`__str_from_i64` / `__print_i64` 的取位循环一直是这个形状：

```quelmara
while v != 0 {
    d = v % 10          // idiv
    ...
    v = v / 10          // idiv
}
```

在 x86 上 `div` / `mod` 都是 `idiv`（20–40 周期，还是微码化的），**而且
两条指令各算一次**。b5_string 做 50 万次 int→str，i 在 `[0, 500000)` 上
平均 5.9 位 —— 约 **590 万次 idiv**。

## 改法：魔数乘 + 反算余数

```
q = umulhi(v, 0xCCCCCCCCCCCCCCCD) >> 3     // floor(v/10)
d = v - q * 10                             // v % 10
```

Granlund-Montgomery 的无符号常数除法，对 64 位全范围成立（不只在
`v < 2^32` 上）。前提是 `v >= 0` —— 两个调用点都在"负数已取绝对值"之后，
且 `INT64_MIN` 走的是单独写定值的分支（v1.29 就有的处理）。

两条 `idiv` → `umulhi + shr + imul + sub`（4 条，各 3–4 周期、可流水）。
`imul` 走的是现成的 `mul_const`（移位加法），不是又一次乘法。

反汇编确认：b5_string 的产物里 `idiv` **从 10 处降到 0 处**。

## 效果（本机 min of 7，双向对照）

| 基准 | 改前 | 改后 | 变化 |
|---|---|---|---|
| b5_string | 83.8 ms | **37.1 ms** | **−56%（2.26×）** |

同一台机器上 C 是 57.9 ms —— 改前 qlmc/stage-0 是 1.4×，改后是 **0.64×**，
即 **stage-0 的 b5 已经比 C 快 36%**。

**这是本项目第一次靠"换一条指令序列"而不是"多做一个优化"拿到 2× 量级的
收益**：前面的 LICM / 越界检查 / 常数除法都是 5–15% 的档位，这次是把一条
20–40 周期的微码指令从热路径上彻底删掉。

## 为什么之前没做

`opt_const_div`（v2.61）已经能做常数除法的魔数化，但它要求
`analyze_nonneg` 能证明被除数非负 —— 而 `__str_from_i64` 里的 `v` 是**运行期
形参**，`analyze_nonneg` 只认"有常量上界的归纳变量"，证明不了，于是这条
路径一直是 idiv。

**教训**：运行时库（`__str_from_i64` / `__print_i64` / `__fmt_u64` 这些）
是编译器自己写的 IR，**不需要靠分析去证**——写的时候直接写成好形状就行。
优化器证明不了的常量除法，在库里可以手工展开。

## 没做的一处

`__fmt_u64`（f64 格式化，递归）里也有 `div 10` + `mod 10`。**故意留着**：
它是递归的、每个浮点只调用位数次，而 b2_float 只在最后打印一次，
不在热路径上；改它的收益测不出来，风险（递归 + umulhi 踩 RDX:RAX）不划算。

## 顺带否掉的一件事

为了让 `opt_bounds_elim` 能删掉 b9_json 每次 `s[p]` 的越界检查，试过
**跨函数的"形参在所有调用点都非负"摘要**（最大不动点：初始假设全非负，
扫调用点删事实）。实现完整、结论正确，但**在十个基准上一个都没命中**：

- b9 的 `p` 来自 `jws(s, p0)` 的**返回值**，而 `jws` 的 `p` 又来自自己的
  形参 —— 需要"返回值也非负"的第二层摘要；
- 再往上一层，jval 里有 `q = jws(s, st.get(0))`，`st.get(0)` 是 vec 取元素，
  非负性不可证 —— 整条链断在这里。

代码已全部回退（不留死路径）。结论写进 `07-gaps.md`：**b9 的 5.3× 要靠
真正的块级范围分析，不是"加个跨函数摘要"**。
