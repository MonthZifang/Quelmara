# v2.89 — 测量校准：本机分辨率只到 ±20%，b8 的微优化已经测不出来

- 日期：2026-10-28
- 任务：性能 —— 先校准"本机到底能测出多大的效果"，再决定往哪使劲
- 结论：**b8/b1 的 <20% 改动在本机不可判**；剩下的路都是结构性的。
  这一版没有代码改动，只有一条校准结论和一次决定性诊断。

## 校准：同一份产物，同一台机器

b8_threads1（160M 次迭代），产物不动，连测 6 次：

```
286 / 286 / 288 / 284 / 309 / 290 ms      ← ±5%（分钟级）
```

但**跨几十分钟**，同一份产物从 278 漂到 360 ms（±15%）。所以：

> **本机能可靠分辨的效果是 ≥20%。** 低于这个数的"优化"，只能靠 CI
> （`bench.yml`，min of 5，固定 runner）判定。

这条不是新发现（`docs/00-convention` 里早有"本机只做粗判"），但**以前没有
量化到具体数字**，于是我在 v2.87/v2.88 里拿 ±15% 的数字做过判断 —— 那是错的。

## 一次决定性诊断：b8 的热循环不是吞吐瓶颈

b8 的守卫版热循环里有一条 `imul r10, r13, 7`，只有慢路用。我把它的 IR 直接
NOP 掉（结果会错，只看时间）：

| | 6 次 |
|---|---|
| 带 imul | 320 / 360 / 320 ms |
| 无 imul | 345 / 327 / 334 ms |

**没有差别**，全在噪声里。结合 v2.88 的"无分支化也没用"，可以定性：

> b8 剩下的时间花在**依赖链和前端**上，"减一条指令"这个层面已经没有收益了。

## 所以这一版什么都没改

代码与 v2.88 完全一致。留着这条记录，是为了**下一轮不要再做无效功**：
b8 想再快，只能动结构。

## 剩下的路（都是结构性的，每个单开一轮）

| 方向 | 预期 | 代价 |
|---|---|---|
| **循环版本化** | 把守卫挪出热循环（b8 −3 条/轮），估计 10~20% | 要复制循环体 + vreg 重映射，风险中高 |
| **尾调用优化** | b3/b7/b9 都是递归；C 靠 sibling call 把它们变成 `jmp`，帧都不开 | 发射器加一条 `TAILCALL` 路径，风险中 |
| **自动向量化** | b1/b8 对 C 的差距**全在这里**（C 是 AVX2 的 48 条/16 元素） | 新一层机器，风险高 |

按性价比：**尾调用优化 > 循环版本化 > 向量化**。TCO 动的是三个基准
（b3 3.50×、b7 1.53×、b9 4.06× 对 C），而且是 C 早就在做、我们完全没做的事。

## 验证

代码零改动，所以回归结果与 v2.88 相同（qlmc 差分 68、主回归 298）。
这一版的可信度来自**测量本身**：`docs/06-status.md §3.50`。
