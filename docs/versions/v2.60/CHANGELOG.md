# v2.60 — 越界检查收成一条无符号比较 + 失败路径不再内联

- 日期：2026-10-26
- 任务：在 v2.59（LICM 默认开启）之上继续优化性能
- 影响面：`tools/stage0/qlm_native.py`（`emit_bounds` / `__vec_get` 等四处
  / `__bounds_fail` / `__vec_fail`）、`tools/stage0/qlm_arm64.py`（COND 表）

## 结论先说

**三个"减少指令数"的改动做了，两个是体积收益、三个尝试被数据否掉。**
本机十个基准的时间**没有可测变化**（校验和 10/10 一致），说明这些基准的
瓶颈已经不在指令数上了。逐条见下面"负面结果"——那部分是这轮最有价值的
产出，能省掉下一轮重复踩坑。

## 改动

**(A) 越界检查：两条比较 → 一条无符号比较**

```python
# 以前（定长数组 / str 下标）
jcc ge idx, n  -> fail
jcc ge idx, 0  -> ok
# 现在
jcc b idx, n   -> ok          # (u64)idx < (u64)n
（否则落到 fail）
```

负下标按无符号解释是巨大值，天然落在"idx >= n"那条失败路径上，所以
"idx >= 0"那次比较是多余的。每次下标访问少 1 条 `cmp` + 1 条 `jcc`。

同样的收法用在 `__vec_get` / `__vec_get_n` / `__vec_set` / `__vec_set_n`
的 `cmpset` 版本（`cmpset l` + `jnz` + `cmpset ge` + `jnz` →
`cmpset b` + `jz`，4 条 → 2 条）。

**(B) 失败路径不内联**

`__bounds_fail` / `__vec_fail` 以前会被 `opt_inline` 内联到**每一个**下标
访问点，每个副本是 `movaddr + WriteFile + ExitProcess`（5-8 条）。b9_json
这种大函数能复制几十份，纯粹挤 I-cache，而这条路径正常情况一次都不走。
现在给它们打 `no_inline`，调用点只留一条 `call`。

**(C) arm64 补齐无符号条件码**

`qlm_arm64.COND` 原来只有 `e/ne/ge/l/le/g`，加了 `b/ae/a/be`
（A64 的 LO=0x3 / HS=0x2 / HI=0x8 / LS=0x9）与对应的 `INV_COND`。
**不加的话 (A) 会让 arm64 后端 KeyError 崩** —— 这是改 IR 条件码时最容易
漏的一处。

## 负面结果（做过、测过、回退了）

这一轮先试了三个"看起来该有收益"的改动，全部被数据否掉。**记下来是为了
下一轮别再试一遍**：

1. **无帧函数（nslots=0 且 frame_words=0 时不压 rbp）**
   省 `push rbp / mov rbp,rsp / mov rsp,rbp / pop rbp` 四条。
   b3_recursion（270 万次调用）三轮 A/B：frameless 8.0/8.8/8.0，
   带 rbp 7.4/7.7/8.8 —— **没有收益，两轮还更慢**。
   原因：`push/pop` 走栈引擎、`mov rbp,rsp` 被寄存器重命名消掉，省的是
   **指令槽位**不是延迟；而 fib 的瓶颈是**调用延迟链**（每次调用等子调用
   返回），不是发射带宽。

2. **`vec.push` 的容量检查内联**（只在需要扩容时才 call `__vec_grow`）
   b4_array 三轮 A/B：28.5 vs 28.4 —— **完全一样**。
   原因：b4 是内存带宽瓶颈（200 万元素 16 MB），push 阶段的调用开销被
   掩盖。b4 的 3× 差距是带宽，不是指令。

3. **LICM 外提 `load`（vec 句柄的 base/len 字段）**
   理论上 b4 的读循环每次 `v.get(i)` 能省两条 load。**实现到一半发现
   不安全，直接放弃**：`load` 会陷入（野指针），而循环可能执行 0 次 ——
   外提就改变了语义。要做必须先做"循环至少执行一次"的证明
   （loop rotation / 常量上界），那是另一个量级的工程。

## 那 3-4× 的差距到底在哪

本轮实测把十个基准的瓶颈归了类：

| 基准 | 差距 | 瓶颈 | 能不能追 |
|---|---|---|---|
| b1_int / b8_threads1 | 3-4× | **C 用 AVX2 向量化**（48 条/16 元素） | 要写自动向量化器 |
| b4_array | 3× | **内存带宽**（16 MB 工作集） | 不能 |
| b9_json | 4× | **jval 的寄存器压力**（198 vreg / 24 溢出槽）+ 每 token 一次调用 | 扩寄存器池（RCX/RDX，需审计 idiv/shift 的隐式寄存器） |
| b3_recursion | 3× | **调用延迟链** | 递归无法内联，追不上 |
| b7_sort | 1.7× | 内存 + 分支 | 部分 |
| b5_string / b6_hash / b2_float | 1.0-1.3× | — | 已经持平或更快 |

下一步真正有空间的只有两条：**寄存器池扩到 11（RCX/RDX）** 与
**自动向量化**。前者需要先审计 `idiv`（RDX:RAX）、变量移位（CL）、
`cpuid`（四个寄存器全占）的隐式使用；后者是一个新层。
