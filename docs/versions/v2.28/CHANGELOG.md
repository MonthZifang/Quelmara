# v2.28 — 位运算与移位 + 进制字面量，子集 S14

- 日期：2026-10-25
- 任务：`& | ^ ~ << >> >>>` 与 `0x`/`0b`/`0o` —— 上一版结尾定位出的**自举第一个硬阻塞**
- 影响面：自举层（qlmc 词法 / 语法 / IR / 发射器）/ 测试 / 文档

## 主事件：位运算与移位

```quelmara
print(12 & 10)        // 8
print(1 << 10)        // 1024
print(-1024 >> 3)     // -128                 算术右移（sar）
print(-1024 >>> 3)    // 2305843009213693824 逻辑右移（shr）
print(~0)             // -1
print(0xDEAD_BEEF)    // 3735928559
```

| 层 | 改动 |
|---|---|
| 词法 | 三字符 `>>>` 优先，然后两字符 `<<` `>>`，单字符 `&` `\|` `^` `~`；**全部直接比字节**（见下面那次 3.3× 回退） |
| 语法 | 在 `_and_e` 与 `_eq_e` 之间插 `_bor_e` → `_bxor_e` → `_band_e`；在 `_rel_e` 与 `_add_e` 之间插 `_shift_e`；`_unary` 加 `~` |
| IR | `OP_AND` / `OP_OR` / `OP_XOR` / `OP_SHL` / `OP_SAR` / `OP_SHR` / `OP_BNOT`（40..46） |
| 发射 | and/or/xor 复用 `_bin_into`（ALU 码 0x21/0x09/0x31）；移位走 `D3 /ext`（计数在 CL）；`~` 走 `F7 /2` |

**优先级照 stage-0 抄，不是 C 的**（SPEC §2.4）：

```
||  <  &&  <  |  <  ^  <  &  <  == !=  <  < <= > >=  <  << >>  <  + -  <  * / %  <  一元
```

所以 `6 & 2 == 2` 是 `6 & (2 == 2)` = **0**（C 会算成 `(6 & 2) == 2` = 1），
`1 + 2 << 3` = **24**，`1 << 2 + 1` = **8**。这三条都进了夹具。

**移位语义**：`>>` 是算术右移（`sar`，符号位扩展），`>>>` 才是逻辑右移（`shr`）。
x86 的 64 位移位会把 CL 自动掩成 6 位，所以 `x << 64` 等于 `x << 0`——stage-0
运行时也不做越界检查，**这里保持一致，没有自作聪明加检查**。

## 顺带补上：进制字面量

写机器码编码必须要有十六进制，qlmc 自己的源码里到处是 `0xFF` / `0x8000` / `0b1010`，
不加这个连词法都过不去。支持 `0x`/`0X`/`0b`/`0B`/`0o`/`0O` + `_` 分隔，
`0x` 后面没数字则 fail-fast（与 stage-0 同口径）。

## 踩坑：词法热循环里用 `substr` 让编译慢了 3.3×

加 `>>>` 判断时顺手写成 `if substr(src, i, 3) == ">>>"`。这段代码对**每个字符**
都跑一次，而 `substr` 每次分配一个新串：

| 版本 | `s3_manyfns.qma`（96 KB）编译 |
|---|---|
| v2.27 | 16.5–19.2 ms |
| v2.28 第一版（每字符 substr） | **54 ms（3.3×）** |
| v2.28 定稿（直接比字节） | **16.1 ms** |

改成 `src[i] == 62 && src[i+1] == 62 && src[i+2] == 62` 就回到原位，还顺带把
**原来就存在**的每字符 `substr(src,i,2)` 也去掉了（所以比 v2.27 还略快）。
判据：`s3_manyfns` 的编译耗时对词法成本最敏感，改词法必测这一条。

## 差分逼出来的 stage-0 bug：打印 INT64_MIN 输出乱码

`1 << 63` 这一行，qlmc 打印 `-9223372036854775808`，stage-0 打印：

```
-'..--).0-*(+,))+(0(
```

长度一样、`-` 和 `0` 一样，其余字符是 `chr(48 - d)`——正好是"取绝对值时
`-INT64_MIN` 溢出、`x % 10` 得负余数、`'0' + r` 打到 `'0'` 以下"的指纹。
qlmc 走 `wsprintfA("%I64d")` 所以是对的。

这是 stage-0 的 itoa bug，**归 stage-0 那条线改**（本线只碰 qlmc，不动对方在途文件），
已记进 `07-gaps.md` §7.19（含一行修法）。夹具里 `1 << 63` 改成
`print((1 << 63) >> 62)`（= -2）——覆盖同一条代码路径但绕开打印 bug。

line 59 是 `fn _CreateFileA(name, access, share, sec, disp, ...)` 这条 7 参 ffi 声明；

## 已知边界

- 位运算只对 int 成立（`~` 对 bool 会当 int 处理），没有窄宽度截断语义。
- **没有常量折叠**：`1 << 10` 在运行时算，不像 stage-0 那样编译期折叠成 1024。
- 移位计数恒走 CL 路径（`mov rcx, x; shl rax, cl` 两条），没有"计数是立即数就用
  `C1 /4 ib`"的 peephole。等有常量折叠时一起做。
- 仍然缺：>4 形参、f64、泛型、宏/反射、接口、`rc`/`Drop`、闭包捕获、
  `vec[vec[T]]`（§7.18）、map 扩容、聚合作容器元素。
