# 文档存放规范（DOC-CONVENTION）

本文件规定 Quelmara 仓库的文档**放在哪、叫什么、写什么、怎么随版本走**。
所有文档改动都必须符合本规范；不符合的由 `tools/dev/check_docs.py` 拦下。

## 1. 目录结构

```
./                              # 仓库根
├── README.md                     # 唯一例外：仓库根导航桩（只放链接，不写内容）
└── docs/                         # 全部文档的唯一存放目录
    ├── README.md                 # 文档索引（入口）
    ├── 00-convention.md          # 本文件：存放规范
    ├── 01-overview.md            # 总览与快速开始
    ├── 02-language.md            # 语言参考
    ├── 03-stdlib.md              # 标准库 API
    ├── 04-compiler.md            # 编译器实现
    ├── 05-toolchain.md           # 工具链与工程化
    ├── 06-status.md              # 实测状态（数字唯一出处）
    ├── 07-gaps.md                # 能力缺口与路线
    └── versions/                 # 版本档案
        ├── archive/              # v1.18 之前的旧日志存档（只读）
        └── v1.18/
            └── CHANGELOG.md      # 该版本的更新日志
```

**禁止**在 `docs/` 之外新建 `.md`（`README.md` 导航桩除外）。
`tools/`、`tests/`、`bootstrap/` 下不放文档——需要说明的内容写进 `04-compiler.md` 或 `05-toolchain.md`。

## 2. 命名规则

| 对象 | 规则 | 例 |
|---|---|---|
| 文档 | `NN-<topic>.md`，两位数字定阅读顺序，主题小写英文 | `02-language.md` |
| 版本目录 | `v<major>.<minor>.<patch>`，与语言版本号一致 | `v1.18` |
| 版本日志 | 固定名 `CHANGELOG.md` | `versions/v1.18/CHANGELOG.md` |
| 编号 | `00` 留给规范，`01`–`07` 为内容文档；新增内容文档用 `08`、`09`… | `08-faq.md` |

编号一旦分配**不再变更**（不要因为插入新文档而重排旧编号，那会让所有历史引用失效）。

## 3. 每份文档的职责边界

一份文档只回答一类问题。判断标准：**读者带着一个问题来，只该打开一份文档。**

| 文档 | 回答的问题 | 明确不写 |
|---|---|---|
| `README.md` | "我该读哪份？" | 任何技术细节 |
| `00-convention.md` | "文档该怎么放、怎么写？" | 技术内容 |
| `01-overview.md` | "这是什么、怎么跑起来？" | 语法表、API 表、性能数字 |
| `02-language.md` | "这个语法/类型/内建怎么用？边界在哪？" | 标准库函数、实现算法 |
| `03-stdlib.md` | "标准库有哪些函数、签名是什么？" | 语言语法、性能对比 |
| `04-compiler.md` | "编译流程是怎样的、我该改哪个文件？" | CLI 参数、语言教程 |
| `05-toolchain.md` | "命令怎么敲、配置怎么写、测试怎么跑？" | 语言语义 |
| `06-status.md` | "现在什么水平？跑分多少？" | 缺口论证、路线 |
| `07-gaps.md` | "还差什么？先做哪个？" | 实测数字（引用 06） |

内容重复是漂移的源头：**同一事实只允许有一处权威表述**，其它地方写链接。

## 4. 数字的单一来源

以下指标**只允许**出现在 `06-status.md` 和 `versions/*/CHANGELOG.md`：

- PE 回归项数（`PASS=n FAIL=n SKIP=n`）
- 自举进度（`n/9`、行数、百分比）
- 对拍结果（lexdiff / parsediff / irdiff / emitdiff / bodydiff 的一致与分叉数）
- 基准耗时（ms / µs / MB/s / cycles per iteration）

其它文档需要引用时，写"见 `06-status.md`"，不要复制数字——复制的那一刻就开始漂移。

> 这条规则来自真实事故：曾出现同一指标在四份文档里分别是 96 / 113 / 116 / 124，
> 而门禁只查短语不查数字，全部放行。

## 5. 版本文件夹规则（每次任务提交必做）

**每一次任务提交（一个主题 = 一个 commit）都必须新建或更新一个版本文件夹。**

### 5.1 什么时候新建

- 新版本号（如 `v1.18`）→ 新建 `docs/versions/v1.18/`，内含 `CHANGELOG.md`。
- 同一版本内的追加提交 → 在已有 `CHANGELOG.md` 末尾追加一节，不新建目录。
- 版本号取"语言版本"，与 `tools/stage0/qlm_cli.py version` 的口径对齐；补丁级可用 `v1.18.1`。

### 5.2 CHANGELOG.md 必含内容

```markdown
# v1.18 — <一句话主题>

- 日期：YYYY-MM-DD
- 任务：<用户要什么>
- 影响面：<语言 / 标准库 / 编译器 / 工具链 / 文档>

## 改动

| 文件 | 改了什么 |
|---|---|
| `docs/02-language.md` | 新增 §x |

## 验证

| 命令 | 结果 |
|---|---|
| `python tests/run_win_tests.py` | PASS=124 FAIL=0 SKIP=1 |

## 已知边界 / 遗留

- <没做完的、故意不做的、下轮要接的>
```

### 5.3 归档

`versions/archive/` 存放重构前的历史日志（`pre-v1.18-changelog.md`），**只读不改**。
历史提交的完整内容可用 `git log` 追溯，归档件只为方便检索。

## 6. 写作纪律

1. **先扫描源码，再写文档**。文档的事实来源是代码与实测输出，不是上一版文档。
2. **每条能力断言附证据**：`文件:行`、或一条可复制的命令 + 期望输出。
3. **不写"应该""大概""差不多"**。做不到就写做不到，并给出复核方式。
4. **改代码必须同步改文档**：能力翻转时，同一次提交里更新 `06-status.md` / `07-gaps.md` / `02-language.md` 中受影响的行。
5. **删掉而不是注释掉**过期段落。历史留在 git 和 `versions/` 里。
6. 中文正文，代码/路径/命令用等宽。表格优先于长段落。

## 7. 门禁

`python tools/dev/check_docs.py` 在 CI 两个 job 里都跑，检查四件事：

1. **过期断言黑名单**：已被证伪的说法（如"元素仅标量"）不得出现在除 `archive/` 外的文档里。
2. **索引完整性**：`docs/` 下每份 `.md` 都必须出现在 `docs/README.md` 的清单里。
3. **版本目录完整性**：`docs/versions/v*/` 必须含 `CHANGELOG.md`。
4. **数字单一来源**：除 `06-status.md`、`versions/` 外，文档里不得出现"回归 n 项"这类实测数字。

新增一种漂移，就把特征加进脚本的 `STALE` 表——**只改文档不改门禁，等于没修**。

另有两道结构性门禁（v3.23）：

- **`tools/dev/check_static_words.py`** —— `static_word(i)` 的槽位登记表。
  解析 `std/**/*.qma` 里所有 `static_word(...)`（跨过注释 / `const` /
  辅助函数三层间接），按槽位归组后判越界 / 抢槽 / 登记表双向一致。
  **改槽位必须同时改 `REGISTRY` 与源码**，只改一边会被打回。
  已挂进 `tests/run_win_tests.py`（`case_static_word_registry`）。
- **`gen_stdlib_doc.py --check`** / **`check_names.py`** / **`check_origin.py`**
  —— 标准库文档、命名、来源标注。
